    任务 06文档核对 · 2026-10-13

    升级并保留原实例

    目标：更换程序镜像，同时保留原资料和身份。前提：设备管理员已确认源版本、目标版本及兼容说明；当前实例健康，有经过核验的停机备份和独立主密钥副本。以下在 NAS 原来的项目操作，不建立替代的新实例。

    本页目录
    • 1. 先记录原来的真实状态
    • 2. 停写、停服务、做保护点
    • 3. 只改目标镜像引用
    • 4. 检查后才恢复写入
    • 失败与回退

    1. 先记录原来的真实状态

    在 NAS 项目界面导出当前 Compose 和有效环境变量，私下记录：

    • 原项目名称和目录、core/gateway 容器 ID、镜像 image ID 与 OCI revision。
    • core 的 /var/lib/lantai、/var/lib/lantai-secrets 的实际卷名或宿主路径。
    • config、setup、Caddyfile、TLS 的实际挂载来源，以及原域名和 HTTPS 端口。
    • /api/v1/meta 的 instance_id；一个可读资源的精确版本 ID 和文件 SHA-256。

    用实际挂载判断，不能根据项目名称猜测卷名。镜像 tag 可以被重复使用，不能单独证明版本。已有实例此时 /setup/ 应为 404。若已有异常、缺卷或出现设置页，停在这里先排查。

    2. 停写、停服务、做保护点

    1. 暂停上传、任务和客户端自动重试。
    2. 在原项目停止 gateway，然后优雅停止 core。选择“停止”，不选“删除项目及数据”。
    3. 按离线备份对原实际挂载执行 backup 和 backup-verify，并另存原主密钥。备份与核验都成功后才继续。
    4. 保留旧镜像和原项目配置。导出 Compose 或容器文件系统都不能代替资料与密钥备份。

    GUI 若不能确认优雅退出，应使用已有管理终端的 docker stop --timeout -1 CONTAINER_ID，等待正常退出；异常退出或一直不退出时保留现场，不直接升级。

    3. 只改目标镜像引用

    1. 在镜像管理器导入已校验的新镜像。
    2. 编辑原项目的有效 LANTAI_IMAGE；若 GUI 不加载它，明确修改 prepare 和 core 两处 image。两处必须一致，保留已核对的 pull_policy: never。
    3. 保持项目名、目录、数据卷、密钥卷、config、setup、TLS、Caddyfile、网络和端口原值。不要用新安装包的 Compose 或 .env 覆盖原配置。
    4. 在原项目应用更新，按新镜像重新创建 core。只点“重启容器”不会更换镜像。确认 GUI 没有勾选初始化、删除卷或清理存储。
    5. core 就绪后恢复 gateway。没有网关变化时不必为升级更换网关镜像、域名或证书。

    rc.3 对“挂错另一个有效卷”“旧卷丢失后新建空卷”没有覆盖全链路的实例绑定保护。prepare-volumes 对已有内容只校验；它不等于证明挂载的是原实例。不要把尚在设计的 external 卷方案临时混入本次升级。

    4. 检查后才恢复写入

    1. 核对新 core 的实际 image ID 和 OCI revision，不能只看标签或 (devel) 版本文字。
    2. 比对原数据/密钥卷身份及全部挂载来源、域名和端口。
    3. meta 返回 200，instance_id 与升级前一致；setup 仍为 404。
    4. 管理员通过已有的本机观测途径核对 /healthz 为正常，/readyz 中 ready=true、business_ready=true、state=ready、reason_codes=[]。不要为此公开 9090。
    5. 使用自己的有效会话读取并下载升级前同一个版本，核对 SHA-256。普通过期会话可按原流程重新登录，不重新初始化管理员。

    缺少内部探测工具或有效会话时，把相应检查记为“未验证”。脚本退出 0、容器 Running、首页 404 都不能替代以上验证。

    失败与回退

    出现 setup 页、实例 ID 改变、卷身份不同：立即停 core/gateway，保留现场，不建立新管理员；恢复原挂载后再检查。别把误建的空卷继续当成原实例。

    固定版本对 rc.2（676de7a）→ rc.3（9bf4b56） 没有新增数据库 schema、服务端资料格式或配置格式迁移，已有隔离合成环境的正反向镜像验证。仅对这对版本、且未做其他迁移/恢复/格式修改时，可在停写停机后恢复原镜像引用并重建 core，再完整核对。它不会撤销 rc.3 已接受的业务写入，也不证明任何现场 NAS 已升级成功。

    其他版本不可推广这个结论。若发生迁移、较新格式拒绝、资料损坏或密钥不配对，先停止。按该版本说明使用兼容的核验备份恢复到新空目录；整馆恢复会重建认证身份，不等于保留原登录的普通镜像回退。
