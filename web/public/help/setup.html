    完成首次管理员设置

    目标：保存管理员登录材料，让全新实例进入正常服务。前提是已完成安装，使用自己的可信 HTTPS 地址。此页只开放一次；已初始化实例不需要再次设置。

    五种材料分别放哪里

    材料从哪里得到填在哪里 / 怎么保存
    setup 引导码NAS 的 setup-code.json 中 code 字段浏览器第一屏“引导码”，只复制字段值
    管理员密码自己或密码管理器生成，至少 12 个字符第一屏“口令”和“再次输入口令”；存密码管理器
    TOTP 设置密钥第二屏上方的长串字符填进验证器的“设置密钥”，不是动态码栏
    6 位动态码验证器的 Lantai 条目，约 30 秒变化一次第二屏“验证器当前 6 位动态码”，保留前导零
    恢复码第二屏密钥下方整组多行内容全部私下保存，勾选已保存；本步骤不用填入验证码栏

    引导码、长串 TOTP 密钥和恢复码都不是 6 位动态码。恢复码用于以后受限恢复，每条只能用一次；普通登录仍用密码与当前动态码。不要把上述材料、二维码或截图发给别人。

    1. 在 NAS 找引导码

    1. 在 NAS 容器管理器打开本项目 core 的挂载列表，找到容器目标 /var/lib/lantai-setup，记下对应的宿主目录。
    2. 在 NAS 文件管理器打开该目录的 setup-code.json，只复制 code 值，不含字段名、引号或 instance_id。它不在数据卷的 db/ 里，也不在密钥卷里。
    3. 若拒绝访问，目录权限 0700、文件 0600 是预期保护。使用已有授权的宿主管理终端或厂商的特权读取方式；没有这种途径时由设备管理员处理，不放宽权限。
    4. 在可信电脑浏览器打开自己的 /setup/，例如合成地址 https://library.example:32444/setup/。

    成功标志：看到“设置 Lantai 管理员”和第一屏表单。若 /setup/ 是 404，先检查下文状态，不删除卷或重新初始化。核心镜像无 shell，docker exec core sh 不是读取引导码的方法。

    2. 在浏览器填写第一屏

    1. “引导码”填上一步的 code。
    2. “管理员用户名”自选，例如 ada；用小写字母、数字、下划线或连字符，长度 1–32。
    3. “口令”和“再次输入口令”填同一个至少 12 字符的密码，先保存在密码管理器。
    4. 点“继续”。看到“保存恢复码并设置验证器”后，开始约 10 分钟有效期。

    成功标志：第二屏出现长串设置密钥、整组恢复码、保存确认框和动态码输入框。当前设置页没有二维码，采用手动密钥方式。

    3. 在验证器添加 Lantai

    可使用支持基于时间 TOTP 的可信验证器。先准备好应用再开始第二屏，避免在安装期间耗尽 10 分钟。

    Mac“密码” App：打开并解锁“密码” → 建立或选择自己的 Lantai 网站条目 → “编辑” → “设置验证码” → “设置密钥”。粘贴浏览器第二屏的长串 TOTP 密钥，点“使用设置密钥”，再保存条目。若提示“保存以查看验证码”，是该 App 还在编辑状态，保存后回账户详情取 6 位码。不要把恢复码粘到这里。

    Microsoft Authenticator：添加账户 → “其他账户 / Other account” → “手动输入代码 / Enter code manually”，名称填自己的 Lantai 标签，密钥填第二屏长串，保存后取 Lantai 条目的当前 6 位码。不是 Microsoft 个人或工作账户登录。

    Google Authenticator 等应用的菜单随版本变化，只有找到“手动输入设置密钥”和基于时间 TOTP 后才继续。找不到时用上面的已说明路线，不把密钥交给在线二维码或验证码生成网站。

    成功标志：验证器显示会变化的 6 位数字。菜单依据见原有详细首次设置指南中的官方链接；不同设备版本的按钮文字可能不同。

    4. 回浏览器完成

    1. 保存第二屏的全部恢复码到受保护备注或离线安全位置，重新打开核对完整性。它们只展示一次。
    2. 勾选“我已安全保存这些恢复码”。
    3. 填验证器里 Lantai 的当前 6 位动态码。快到换码时等下一组，不混空格或丢前导零。
    4. 点“完成设置”。看到“管理员已建立”“服务正在启动”后保留全部登录材料。
    5. 点“查看服务状态”或打开同域 /api/v1/meta。正常服务返回 HTTP 200；稍后 /setup/ 返回 404。

    成功标志：meta 200 且 setup 404。旧 rc.2/rc.3 无静态网页时根路径可 404；rc.4 正确挂载后根页应提供登录/首页，404 要排查静态包与网关。管理员登录及资源浏览接着看账户和日常操作。

    登记过期或验证码失败

    Enrollment expired; start again 表示这次第二屏登记过期，或达到 5 次验证码尝试；不是资料丢失，也不要求重装。

    1. 仅在确认尚未完成设置时，刷新同一个 /setup/ 回第一屏。若变成 404，先按下节检查结果。
    2. 继续用原引导码填写第一屏。Wait before restarting setup 时等至少约 10 秒再试。
    3. 新第二屏会给出新的 TOTP 密钥和恢复码。替换验证器中尚未完成登记的旧密钥和旧恢复码草稿，使用新条目的动态码。
    4. Verification failed 时核对设备自动时间、是否用了新密钥、是否是本次 Lantai 条目。不要无限重试。

    点完成后断线，先查结果

    当前状态下一步
    meta 200，setup 404已完成，保留刚才那组密码、TOTP 和恢复码
    setup 仍显示第一屏核对网络和地址，保留旧材料后重新登记
    setup 404，但 meta 未正常可能已保存管理员但激活未完成，交管理员检查原 core/gateway
    Administrator saved; restart the service to retry activation管理员已写入；保留凭据，检查并重启同一实例，不重新注册
    Invalid setup code核对本实例的 code 值，没有复制整个 JSON 或另一实例的码

    只有 setup 404 不能证明服务完全就绪。结果不确定时先保留材料，不删除数据库、密钥、卷或 setup-code.json；更不要执行会删除卷的项目清理操作。
