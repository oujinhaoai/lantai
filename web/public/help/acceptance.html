    人工验收步骤

    目的：让验收人员按当前网页逐步操作，留下可复核的实际结果。本文使用 manual-check-demo、sample.txt 等合成示例，不授权操作真实项目、NAS 卷、用户电脑权限或生产素材。手册说明能力与操作方法，不替任何环境预填“通过”。

    开始前

    1. 核对设备管理员给出的原 HTTPS 地址、实例、核心标签及本次 Web manifest。r11 是 Web 更新，兼容已交付 r10 核心；本轮不改变 schema。
    2. 选定已批准的空合成项目，或由有权管理员按下一节创建。普通验收不需要先看 API、数据库或代码。
    3. 在自己的合成工作目录准备 sample.txt，内容例如 Lantai synthetic acceptance.。记录实际文件大小和 SHA-256；编码、换行改变会使摘要改变，应以真实源文件字节为准。
    4. 准备私有验收记录。只保存脱敏的 ID、大小、摘要、错误和结果；不保存密码、动态码、恢复码、私钥、会话令牌或临时下载地址。截图避开登录表单和秘密显示区域。
    5. 基础验收先做读写小闭环。整馆备份会暂停全部业务，须另有批准的备份窗口；恢复只在隔离空目标另行安排。

    创建项目与权限

    先按创建项目与权限操作。检查“服务器操作回执”的 project_id、created_by、说明修订及 pending/error；项目登记成功后，不因“我的项目”暂时看不到而重建项目。

    在“系统管理”→“项目与成员权限”，使用回执中的明确 project_id 读取成员。管理员按职责授予 viewer 或 contributor；需要写入的本人重新登录并明确选择“素材写入与整理（迁移、工作集档案和信息编辑）”。角色与本次会话范围都满足后才开始下一步，不直接把所有测试者升为 owner。

    五入口操作

    按五入口操作指南中的“用途、前提、路径、示例、步骤、成功标准、失败处理、证据”逐项执行。先用迁移中心入藏这一个 sample.txt，再对其固定版本完成素材查看和工作集检查；表格中的次序不是侧栏的新排列。

    用例操作与预期必须保留的非秘密证据
    素材库找到已授权素材，打开固定版本；预览后实际下载并比较大小及完整 SHA-256。按权限修改当前摘要并重开asset_id、version_id、源与下载摘要；著录原/新 revision。仅点击下载不能判为字节完整
    迁移中心显式选择 sample.txt，审阅分组与 rights，保存原状态后按原键入藏，再核验全部固定文件与完整台账原批次/operation、逐项提交结果、完整文件摘要；失败、unknown、未开始行不删除
    工程工作集加入已知固定版本，检查清单与依赖，拉取并核验 TAR；保存档案，显式“读取项目工作集记录”，从列表重开输入摘要、固定版本、解出的实际文件摘要、档案自己的 asset/version、列表重开结果
    备份与恢复获准窗口由管理员读取目录，确认目标与新鲜动态码后“立即备份”，等完整包验证完成job.id、backup_id、包大小/摘要、完成时间；独立恢复未做就填“未测”
    系统管理创建合成项目，按明确 ID 读取成员，核对所需测试角色的授予或撤销回执与最新修订项目回执、created_by、说明状态、成员修订、操作结果；不记录动态码和授权秘密

    人工验收与判定

    1. 每个用例先写预期，再操作并写实际；填“通过／失败／未测／阻塞”之一。未显示按钮、尚未执行、只有回执或只有截图均不能代填通过。
    2. 改标题、摘要或画像只改变当前著录 revision。核对固定文件 version_id 仍是原值；不要把著录 r1→r2 写成文件产生 v2。工作集档案的新版本也不自动使原素材或旧工作集引用漂移。
    3. 下载后用本机可信校验工具比较实际文件大小与完整 SHA-256。预览成功、链接签发成功、Range 请求成功或下载按钮被点击，各自都不能替代这一项。
    4. 工作集保存后，显式重新查询列表；索引尚未追平时稍后再次点击同一查询。必须从返回列表打开并重新核验，记录实际采用的路径。若只能按固定 ID 打开，列表发现一项仍记失败/阻塞。
    5. 记录整个明确选择的批次，包括 committed、description_pending、failed、unknown、not_attempted。当前文件完整不等于工程可继续编辑；缺原生续做、恢复或设备证据时，整体接受仍可能 blocked/unknown。
    6. 备份生成通过与独立恢复通过分开记录。未在隔离空目标完成管理员因素确认、恢复接受、版本/字节重读和重启，就不能填“恢复通过”。

    常见问题与停止条件

    • 项目创建后不可见：先按创建回执的 project_id 读取成员，核对本人角色与当前会话范围，见项目可见性。不要重复创建或清空卷。
    • description_pending 或著录错误：保留已提交身份与原键，记录部分成功；不重传成另一个资产，也不把 pending 删除为完成。
    • 出现权限拒绝、修订冲突、过期会话、未知副作用、输入摘要改变或源文件不符：停止下一步写入，保留原状态，由有权人对账，不换键猜测重试。
    • TLS 错误、实例不符、文件摘要不符、缺卷、损坏或恢复未完成：停止验收；不跳过证书校验、删除锁或新建空卷冒充恢复。
    • schema14→15 后旧核心不能直接同卷降级。旧 rc.6 格式恢复已验证的路径仍涉及 recover-admin、绑定证据的 restore-complete 和恢复目标配置；NAS 纯 GUI 旧版恢复尚未验证，缺口不能写成可用步骤，见备份与恢复。
    • 设备八动作、M1-07 改链/rollback/最终接受、工作集新版本回交和真实 DCC 打开编辑须按对应范围另验。不能把本页五条基本路径或手工勾选扩为全功能验收。

    其他错误见常见问题与版本兼容。只交付实际证据，不能因手册已经更新就推定现场已通过。
