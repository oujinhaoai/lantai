# M1 查询投影与内部重同步

所有者：T04 `query`。本契约说明 M1 已实现的核心 Go 接口；公开 HTTP 事件查询、长轮询和收件箱仍属 M2。

## 权威边界与投影

`index.db` 只有可删除的目录、文本和版本关联投影，以及投影构建代次、消费水位、事件去重与对象修订。版本枚举走 `commit.Reader.Versions`；目录与清单通过 `catalog.ReadProjection` / `ReadProjectionVersion` 读取台账指向的不可变文件并验证摘要。磁盘上没有 committed 登记的目录不进入索引。查询失败不会阻止台账命令或 catalog 精确读取。

目录摘要只含资产/项目/当前版本 ID、类型、slug、标题、摘要、标签、主题与著录修订。文本检索对这些著录字段进行 NFC 规范化、不分大小写的字面子串匹配；不索引 `uses.declared`、源文件路径、自由格式证据或许可证据。M1 不承诺语义搜索、相关性排序或 FTS 查询语法。

关联投影覆盖所有已提交版本的固定 `uses`。响应前逐一复验关系两端的当前读取权限与 `archive_review` 用途，隐藏来源的 ID、路径、关系、数量均不返回。跨实例来源不在 M1 的本地关联查询中显示。

## 当前授权与分页

`Search`、`Relations`、`Snapshot`、`Changes` 在实例 `security_guard` 共享锁内组装响应，逐对象查询当前 T01 授权和 T03 来源/许可限制。当前资产著录为 `personal` 时另查 `personal.read`，不能以旧投影或普通版本清单放宽访问。来源证据待核验时按隐藏处理，不能默认放行。

目录按 `asset_id` 升序分页；每页默认 50 条，最多 200 条，单页最多检查 1024 个候选对象。授权过滤后可能为空但仍有下一页。分页游标以进程随机密钥做 AEAD 加密，绑定主体、会话、过滤范围、构建代次、消费水位与扫描位置；不在明文里泄露被过滤对象 ID。索引更新、重建、进程重启或改变查询范围后，旧游标返回 `CURSOR_EXPIRED`。客户端应从第一页重新读取。

## 重建与增量

`Rebuild` 执行以下顺序：

1. 捕获事件收录高水位 `S`。
2. 分页扫描权威已提交版本，读取当前著录与不可变清单。
3. 固定扫描结束后的高水位 `E`，重放 `(S,E]`，逐受影响资产重新读取权威事实。预留 ID 在扫描游标经过后才提交的版本也由此补入。
4. 在 index 的一个事务中替换整个投影、去重记录与修订水位，构建代次加一，保存 `rebuild_start=S`、`high_water=E`。失败时保留原代次。

如果 S 在重建期间超出事件保留窗口，返回 `CURSOR_EXPIRED`，重新开始完整构建；不发布无法证明覆盖起点的快照。重建与增量串行化，共用实例维护屏障。`Search`、`Relations`、`Changes` 的只读查询可在维护期间执行；`Snapshot` 先调用 `CatchUp`，因此受写入维护屏障限制。真实 `events.Store` 接线时自动登记 `query` 为关键消费者；只有 index 事务已提交且释放写入锁后才上报保留水位。确认失败返回携带已提交状态的 `RetentionPendingError`，再次 `CatchUp`（即使无新事件）补确认；不提前确认，也不因跨库确认失败回滚已发布代次。

`CatchUp` 固定本次结束水位，逐页（最多 256 个事件）处理：先在读者锁外读取权威事实并计算投影，同一页内同一资产只刷新一次；再在每页 index 事务内提交投影、`event_id` 去重、对象修订和消费水位。页与页之间释放读者锁，追赶期间 `Search` 等读取看到某个已提交页边界上的完整状态，不会被整段追赶阻塞；`Rebuild` 扫描与重放期间读者继续看上一代，只有整代替换事务持有读者锁。增量与重建由单独的写者互斥串行化。事件 payload 只定位对象，不作为可见事实。乱序事件按对应事件族、aggregate 类型和 ID 的修订对账；不同业务修订序列不能只因 ID 相同而互相跳过。更高修订先到时直接重读权威当前态，旧事件不会把投影回退。相关事件 schema 不兼容或文件验证失败时整页回滚，不推进消费水位。

单资产刷新通过权威 Reader 的 `AssetVersions` 按资产读取版本登记（台账走 `(asset_id, version_number)` 唯一索引），代价与该资产的版本数相关，与全库规模无关；不建立第二份权威清单。全量重建仍按版本 ID 扫描全库一次，在内存中准备完整候选代次，适用于当前 M1 范围，后续大库可增加磁盘暂存代次而不改变事务可见点。

## 内部同步模型

`Changes(after, limit)` 读取有界事件页，再按当前授权返回重新核对的目录摘要，不转发原始 payload。即使所有事件都被过滤，`high_water` 仍为已扫描水位。权限、会话、策略、来源限制或生命周期变化标记 `resync_required`，调用者必须重新替换可见范围，才能移除撤权后无法继续返回详情的旧条目。过期事件游标明确返回 `CURSOR_EXPIRED`。

`Snapshot` 先捕获 S，再使索引消费水位至少达到 S，在同一代次和授权锁内取得完整过滤范围。返回 `replace_scope=true`、过滤条件、条目及水位；客户端先移除该范围的旧条目再安装返回条目，随后从返回水位增量读取，不能把重同步当仅追加合并。若索引尚未构建或已落后于事件保留窗口，先执行 `Rebuild` 再取得快照。

验证入口：`go test ./internal/query`。测试包含删除 index 后重建、当前撤权/personal/来源限制、隐藏关联、全部过滤仍推进水位、过期游标全量替换、乱序修订、扫描期间旧 ID 提交后的重放、投影写入失败同事务回滚、失败重建保留旧代次与分页范围绑定。
