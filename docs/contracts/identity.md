# 身份与授权

状态：**M1 第一版，已实现并有自动化测试**（T01.1–T01.5 的 M1 部分及 T01.6 的服务端接线）。实现：[`internal/identity`](../../internal/identity/)；动作、角色与策略的登记表由生成器输出：[动作与策略登记](identity-actions.md)。REST 与远程 CLI 已按本篇接线，具体入口见 [HTTP 契约](http.md)和[客户端契约](client.md)；资源审定、解锁、清除等 M2 敏感动作沿用同一机制另行登记。

本机制防止 Agent 凭普通会话或已登录的浏览器扩大敏感操作；它不宣称能对抗已控制同机高权限账号或进程的攻击者。

## 主体、角色与能力

- 主体类别只有 `human`、`agent`、`node`、`worker`、`runner`、`service`，**由管理员登记时决定**；请求里没有“我是人”一类字段，会话类别只来自登记。名称按类别约束且注册后不变：人 `ada`、Agent 身份 `<Agent 类型>@<节点>`、`node:<节点>`、`worker:<名称>@<节点>`、`runner:<名称>@<节点>`、`service:<名称>`。
- 主体停用不删除，历史记录中的身份保留可查；停用推进 `auth_epoch`，其全部会话、子会话与委托立即失效，重新启用也不复活旧会话。
- 项目角色：`owner`、`coordinator`、`contributor`、`curator`、`checker`、`reviewer`、`viewer`；系统角色 `admin` 只授予人。角色矩阵见[登记表](identity-actions.md)。
- 档案中的能力标签（`blender`、`gpu` 等）只用于任务匹配与调度，**任何授权判定都不读取它**。
- 项目的稳定 ID 与说明归 catalog；身份模块只记成员、角色与项目策略的修订（`identity_projects`），项目内动作按主体在该项目的角色判定。对无任何角色的项目返回 `NOT_FOUND`，不泄露存在性。

## 凭据与会话

| 凭据 | 形态 | 保存 | 用途 |
|---|---|---|---|
| 长期凭据 | `ltk_` + 32 字节随机数 | 只存 SHA-256 与明文前缀（`ltk_` 后 8 位） | 只能换会话；默认 180 天，不发给人 |
| 会话令牌 | `lts_` + 32 字节随机数 | 只存 SHA-256（runtime.db） | 调用业务接口；默认与上限 12 小时 |
| CSRF 令牌 | `ltc_` + HMAC(主密钥派生子密钥, 会话 ID) | 不存储 | 浏览器会话的写请求 |
| 口令 | Argon2id（默认 64 MiB、3 轮、单线程），参数随记录版本化 | 盐 + 校验值 | 人的登录 |
| TOTP | RFC 6238，6 位、30 秒、前后 1 步 | 种子经主密钥 AES-256-GCM 加密，附加数据绑定因子与主体 | 登录与人类授权 |
| 恢复码 / 设置码 | 16 个 Crockford Base32 字符 | 盐 + SHA-256 | 因子恢复 / 新成员设置 |

- **换会话**：Agent、节点、执行器、运行器、服务用长期凭据换会话；范围与项目只能在凭据之内收窄，有效期不超过凭据剩余期限与 12 小时；档案可限制同时有效的独立普通会话数（`QUOTA_EXCEEDED`）；配额与签发在同一 runtime 事务内，按当前主库吊销、凭据和恢复代次排除失效会话，派生与委托不重复计费。节点、执行器、运行器的范围互不通用，Agent 与服务永远拿不到 `admin`。
- **人的登录**：口令加当前动态码，得到普通会话（CLI 为进程内存会话，网页为 Cookie 会话并附 CSRF 令牌）。登录**不开启任何敏感操作窗口**；成功的动态码时间步随即作废。主体不存在与口令错误返回同一错误，耗时相近。
- **子会话**：`NarrowSession` 从 Agent 等非人主体的会话派生更窄的子会话（交给子 Agent 或子进程），父会话失效时子会话随之失效；最多嵌套两层。人的会话不能派生子令牌（要交给工具时用委托），浏览器会话、恢复会话与委托会话也不能派生；子会话、委托会话与恢复会话都不算“人本人的交互会话”，不能通过仅人本人的检查，也不能申请人类授权。
- **委托（短期能力）**：`IssueDelegated` 为插件宿主、adapter 等代为调用者（`service` 或 `runner` 主体）签发短期会话：权限来源仍是被委托主体，`DelegatedBy` 记录实际调用者；动作与项目必须显式列出且都在被委托主体当前权限之内（查看自己、结束自己不受此限）；不能包含管理、人类授权或恢复动作；有效期不超过 1 小时与父会话剩余期限；父会话或委托方任一失效即失效；不能再委托。代为调用者只拿到这一短期令牌，永远拿不到长期凭据、人类授权或会话 Cookie；委托会话的传输档位一律为批量。
- **会话核对**：每次 `VerifySession`、`Authorize` 都读取当前权威状态——会话是否结束或到期、是否被管理员吊销、实例 `recovery_epoch` 与主体 `auth_epoch` 是否仍是当前值、主体是否停用、换取它的长期凭据是否吊销、父会话与委托方是否仍有效、恢复会话的恢复操作是否仍在进行——不使用缓存。已结束、旧代次、吊销返回 `TOKEN_REVOKED`，到期 `TOKEN_EXPIRED`，未知 `AUTH_REQUIRED`。

## 最终接受与撤权顺序

- 撤权类写入（停用主体、吊销凭据或会话、角色与策略变更、因子重置、恢复开始、结束会话）持 `security_guard` **写锁**并在主库提交后才返回。
- 业务模块的最终接受边界调用 `Accept`：经维护屏障取 `security_guard` 读锁与资源锁，在锁内按当前权威状态授权，允许时执行所属业务库的提交。下载等读取开始调用 `BeginRead`，只取读锁，在锁内授权并打开响应。
- 结果：撤权返回成功之后开始的接受与读取一律拒绝；撤权开始前已在锁内提交的结果保留。已经开始发送的单次响应可能完成，不宣称能收回已交付的字节。
- 需要人类授权的动作，`Authorize` 一律返回 `HUMAN_PROOF_REQUIRED`，只能经敏感命令执行。

## Challenge → HumanGrant → 敏感命令

M1 需要人类授权的命令是凭据与策略管理：登记、修改、停用、启用主体，签发与吊销长期凭据，授予与撤销系统角色和项目角色，实例与项目策略，重置他人因子，吊销会话。

1. 人的普通、非委托会话以完整命令申请挑战（`CreateChallenge`）。服务端校验资格，生成 `operation_id`、目标集合摘要、`request_hash`（`lantai.request-hash/v1`）与待批准摘要文本，挑战 5 分钟有效。界面必须完整展示服务端给出的摘要与目标，不能用 Agent 提供的文本代替。
2. 人在自己的终端或浏览器输入动态码兑换（`VerifyChallenge`）。校验、推进因子的 `last_accepted_counter` 与写入 HumanGrant 在主库同一事务完成：**同一成功时间步不能再用**（登录用过的码、兑换过其他挑战的码都返回 `TOTP_REPLAY`）；挑战只能由发起它的会话兑换（否则 `HUMAN_GRANT_MISMATCH`）；每个挑战最多失败 5 次后锁定；主体与来源另有 10 分钟 10 次失败的限速（`RATE_LIMITED`），新建挑战不能重置。HumanGrant 5 分钟有效。
   限速分两组计数：未认证入口（登录、恢复码、设置码）的失败谁都能制造，已认证会话内兑换挑战与确认新验证器的失败只能由持有会话的人制造。两组互不影响——只知道管理员名的匿名者刷满登录限速，不能锁住管理员用已有会话兑换挑战（例如紧急吊销被盗凭据）。未认证入口在慢口令校验之前、在一个串行化事务中核对限速并预记失败，成功后撤销；并发的错误尝试也逐次计数。
3. 执行（`Execute`）持 `security_guard` 写锁，在主库一个事务中核对：同一人、同一会话、同一动作、相同目标集合摘要与 `request_hash`、未吊销未过期、`auth_epoch` 与 `recovery_epoch` 仍是当前值，以及当前权限与预期修订；然后写入效果、命令回执与 outbox。任一不符返回 `HUMAN_GRANT_MISMATCH`（`details.reason` 指出不符项）或 `HUMAN_PROOF_REQUIRED`（`grant_expired`、`grant_revoked`）。
4. 同一 operation 已提交时只按**当前**权限重放原回执，不再核对已过期的授权，也不产生第二次效果；同一授权不能换幂等键复用（`IDEMPOTENCY_CONFLICT`）。一次性明文（新长期凭据、设置码）只在首次执行的结果中返回，不写入回执或事件——响应丢失后无法取回，只能吊销后重新签发。
5. 授权过期而操作未提交时，可用 `Rechallenge` 为同一 operation 按**同一**动作、目标与请求重新挑战；换目标必须新建操作；已提交的操作不再挑战。

## 恢复

| 场景 | 入口 | 结果 |
|---|---|---|
| 首个管理员 | `lantai init`（本机、持数据根锁、实例未开放服务） | 口令、TOTP（以当前动态码确认后才写入）、10 个恢复码；初始化随即永久关闭。主库已有主体或初始化已关闭时拒绝；数据库丢失不会重新开放初始化 |
| 验证器丢失 | 口令 + 一个恢复码（`StartRecovery`） | 主库一个事务中消费恢复码、推进 `auth_epoch`（旧会话失效）、停用旧因子、吊销人类授权、进入 `reset_pending`；得到绑定该恢复操作的**受限会话**。同一操作可用同一个或同批其他未用码继续；已消费的码不能开启另一个操作 |
| 新成员、或被管理员重置 | 管理员经人类授权登记或重置，得到一次性设置码（24 小时）；本人 `StartSetup` | 受限设置会话；重置在主库同一事务中清除历史口令，必须重新设置口令后才能确认新因子 |
| 恢复码也丢失、只有一位管理员 | `lantai recover-admin`（本机、服务停止、需要主密钥、输入确认短语） | 推进 `auth_epoch`、吊销授权、停用旧因子、作废恢复码与设置码、写入新口令与新因子、生成新恢复码，主库写审计事件并在 `logs/` 追加本机审计行 |
| 从备份恢复整馆 | `InvalidateForRestore` → 新密钥下 `BeginOfflineReset` / `Confirm` → `VerifyRestoreAdministrator`（本机维护屏障内） | 全部旧认证路径失效；只在新管理员密码与 TOTP 已确认、其他恢复检查完成后解除恢复锁定 |

受限恢复/设置会话只能查看自己、设置口令、登记并确认新验证器；它**不能读取资源、提权、派生会话或申请人类授权**。确认新验证器后：启用新因子、作废全部旧恢复码并生成新的一批（只展示一次）、作废设置码、结束受限会话；之后用口令与新动态码重新登录。管理员不能用重置命令重置自己。

设置口令与登记因子的最终会话复验和写入处于同一 `security_guard` 读锁内；口令慢哈希在锁外完成。确认新验证器在主库同一事务中检查并累计已认证入口的失败限速，重新登记因子不能重置主体计数。

`ConfirmFactor` 以主库提交为完成点：账户进入 `enrolled` 后，该恢复操作的全部受限会话立即失效。runtime 会话结束标记失败时，成功响应仍交付新恢复码；内部维护方法 `ReconcileRecoverySessions` 可依据主库账户状态重复补记遗留会话，不关闭新恢复操作的会话。该方法需由后续运维接线显式调用，目前没有自动运行器；它不恢复或再次展示一次性恢复码。

主库迁移 `0003.identity.setup-password-reset` 清除升级前遗留 `setup_pending` 账户的口令，升级时尚未完成设置的人需重新设置一次口令。已登记账户和使用口令加恢复码进入 `reset_pending` 的自助恢复保留原口令。

### 整馆恢复的凭据收敛

operations 先持久推进实例 `recovery_epoch`，保持恢复锁定，并用单独恢复的旧主密钥通过 `CheckStartup`。`InvalidateForRestore(ctx,runID,epoch)` 必须取得同一实例仍有效的独占维护上下文，且 epoch 与实例当前值相同并至少为 2。首次调用还会自行解密核验旧活跃因子，错误主密钥不能借“先停用再检查”掩盖。

身份模块在 main 一个事务中推进全部主体的 `auth_epoch`、吊销全部机器长期凭据、删除旧密码校验值、停用 enabled/pending TOTP、作废全部恢复码（包括可继续旧操作的已消费码）和设置码、吊销 HumanGrant、使挑战过期，并把人的账户置为待重新设置。主体、角色与历史记录保留，原本停用的主体不会被重新启用。普通人的旧密码/TOTP 因此也不能在恢复后重新换取会话。

同事务写入 `identity_restore_runs` 的 run ID、epoch 和失效时间；同 run/epoch 重试不重复修改主库，同键换 epoch 或同 epoch 换 run 拒绝。此离线步骤还没有已验证主体，审计事实由持久 run 记录承载，不伪造事件 `actor_id`。runtime 在独立事务补记旧 epoch 会话结束，失败不会撤回主库失效事实，重试也不会结束新 epoch 会话。

密钥轮换与磁盘恢复阶段归 operations/application。`BeginOfflineReset` 和 `Confirm` 保留原有本机初始化/未服务约束；在 `recovering` 状态仅接受同 Gate 的活跃独占维护上下文，并使用 `security_guard` 写锁。新密码、新确认 TOTP、恢复码、`identity_restore_admin_resets` 的 run/主体/auth_epoch/factor 引用及既有离线恢复事件在同一个 main 事务提交，不能先记“已重置”再补凭据。

`VerifyRestoreAdministrator(ctx,runID,principalID)` 在同一维护屏障与安全读锁内检查该精确 run 的当前恢复代次、已完成重置引用、当前 active human/admin、已登记账户、密码记录及当前密钥能解开的对应 enabled 因子。时间戳相同不影响前后顺序判断；run 之前的重置、改角色、缺密码、旧因子或旧 epoch 都不能通过。响应丢失或恢复中断后重复清理不会覆盖新的管理员设置。身份核验只证明此项凭据条件，解除恢复锁定还须经过运维对旧备份后撤权/删除/未决操作的完整对账。

## 浏览器与 CLI 凭据处理（服务端防护）

HTTP 层防护在 [`internal/identity/httpauth`](../../internal/identity/httpauth/httpauth.go)，由 transport（T07）挂载：

- CLI、SDK 用 `Authorization: Bearer <lts_…>`；不做 CSRF 检查，但仍须通过正常授权。长期凭据 `ltk_…` 不被接受（`long_lived_token_not_accepted`），浏览器会话令牌也不能当 Bearer 使用（`channel_mismatch`）。
- 网页用 `lantai_session` Cookie：`HttpOnly`、`Secure`、`SameSite=Strict`、不设 `Domain`、`Path=/`。非安全方法（GET/HEAD/OPTIONS 以外）必须带与允许列表**精确相同**的 `Origin`（缺失或 `null` 一律拒绝，`origin_missing`；不在列表 `origin_not_allowed`；`Sec-Fetch-Site: cross-site` 拒绝），并带 `X-CSRF-Token`，其值须与该会话相符（`csrf_invalid`）。SameSite 只是额外的一层。
- 同一请求同时带 Bearer 与会话 Cookie 时拒绝（`ambiguous_credentials`）。
- 安全方法不得有业务副作用；401 带 `WWW-Authenticate: Bearer`，错误响应不缓存。
- CLI 的会话令牌放在进程内存或环境变量，长期凭据文件权限 600，客户端细节由 T07.2 实现。

## 数据与事件

- main.db（identity）：主体、系统与项目角色、项目访问控制修订、策略、长期凭据、人的因子状态、口令、TOTP 因子、恢复码、设置码、挑战、人类授权、管理员吊销的会话、认证失败计数、恢复 run/管理员重置引用，以及实例级 `policy_revision` 与初始化状态。
- runtime.db（identity）：会话运行记录。会话吊销的权威记录与命令回执同在主库，验证时两处都核对。
- 事件（outbox）：`principal.*`、`project.*`、`policy.*`、`human_grant.*`、`session.*`，只含状态与引用；口令、种子、恢复码、设置码、令牌及其摘要都不写入事件、回执、日志或素材目录。
- 主密钥单独保存（默认 `secrets/master.key`，可配置到单独受控的位置），与数据根分开备份；启动时逐一实际解密 `enabled`/`pending` 因子并检查种子长度，密钥 ID 相同但内容不匹配或密文损坏也会阻止开放服务；诊断不输出种子。

## 已知限制

- REST 与 CLI 已接入真实身份模块；完整网页尚未建设。网页 Cookie 与 Origin/CSRF 契约由 HTTP 自动化测试验证。
- 资源审定、解锁、清除、限制解除等 M2 敏感动作与批次授权（逐项子操作）尚未实现（T01.5 的 M2 部分）。
- 限速按主体与来源（客户端地址）计数，来源由 transport 提供；经网关转发时需由 T07/T08 确定可信的来源地址。
- Argon2id 参数在开发机上约 0.1 秒一次；目标 NAS 上的耗时须实测后再调整（只影响新记录）。
