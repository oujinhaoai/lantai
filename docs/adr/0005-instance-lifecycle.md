# 0005 实例标记、单实例锁、按库迁移与维护屏障

状态：已采纳（2026-09-27）。规则全文见[实例生命周期、迁移与维护屏障](../contracts/instance.md)。

## 背景

T08.1 要求重复写同一数据根的实例被拒绝、迁移或恢复未完成时业务不可就绪、后台写入也服从维护屏障、迁移按库与表所有者管理且不跨库事务；T01.2 要求实例标记存在而库缺失时进入恢复诊断，不能重新开放管理员初始化。

## 决定

1. 数据根下的 `instance.json`（`lantai.instance/v1`）是“这个目录已属于某个实例”的唯一标记，原子替换写入；初始化先写 `initializing` 标记再建库，完成后改为 `active`。标记存在而权威库缺失时拒绝启动，不创建空库。
2. 单实例锁用操作系统的文件锁（Unix `flock`、Windows `LockFileEx` 锁文件末尾之后的一个字节），进程崩溃即释放，不用 PID 文件。
3. 每个库新增 operations 维护的基础设施表 `instance_binding`（登记在所有权表中），启动时核对五库都属于同一实例。
4. 迁移按库编号，文件名写明所有者；每个迁移与版本记录同事务提交，并核对新建的表都属于该所有者。已应用迁移按内容摘要核对，发现改动或更新的版本即拒绝启动。
5. 兼容矩阵 = 数据格式版本 + 每库最高迁移版本。迁移只经显式命令在维护屏障下执行，中断记录在实例标记中，重跑续做。
6. 维护屏障由 `commands.Gate` 实现：写入口在实例未开放时立即返回 `MAINTENANCE_MODE`，而不是排队等待；维护先关闭写入再取屏障独占锁；写入口代次保证等锁期间经历过维护的写入不会在维护结束后接着执行。后台任务由实例登记与回收，写入同样经 Gate；启动步骤持屏障独占锁运行。
7. 优雅退出在在途写入没有排空时不释放数据根锁、不关库：宁可让进程退出时由操作系统释放，也不让第二个实例在旧写入提交前取得写权。
8. `config.yaml` 采用 schema 校验并拒绝未知字段；密钥不进配置。

## 后果

- 本机命令 `lantai init`、`migrate`、`doctor`、`recover-admin` 都需要（或只读地检查）数据根，服务端监听与健康接口由 T07.1/T08.4 接入 `Readiness()`。
- 迁移不自动做备份；T08.2 完成前，升级真实数据须先人工完成一致备份。
- 网络文件系统只识别已知类型；三平台实际文件语义与故障演练仍待 TEST-M1-06/12。
