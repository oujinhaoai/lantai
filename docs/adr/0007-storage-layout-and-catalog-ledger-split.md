# 0007 资源与存储（T02）的实现取舍

状态：已采纳（2026-09-27）。规则全文见[存储](../contracts/storage.md)与[目录](../contracts/catalog.md)。

## 背景

T02 要在台账（T03）尚未实现时交付可靠的内容接收、授权下载、幂等安装与引用解析，并守住“文件为内容真源、台账裁决提交与生效、知道哈希不等于有权使用”的边界。公共契约（T00）只定义了版本提交与安装证明，缺少占名、说明修订、项目登记与限制查询的接口。

## 决定

1. **补齐跨模块契约，而不是在 T02 里越界实现台账**：`commit` 增加按号/最新版本与资产登记读取、`Namespace`（带代次的占名查询）、`Metadata`（说明修订的保留与生效）、`Projects`（项目登记）与 `Ledger.Cancel/LookupPrepared`；新增 `rights.Evaluator`（用途与来源限制）。内存桩与契约套件同步扩充，真实台账须通过同一套件；最终提交在统一屏障与安全锁内调用本地只读 `AcceptanceVerifier` 复验固定输入、用途与复用授权，保持锁直到提交。
2. **数据目录按稳定 ID 命名**（`projects/<project_id>/assets/<asset_id>/versions/vNNN/`），不按可变路径：名称复用、改名、回收站恢复与 Windows 路径长度都不影响版本目录；人读的路径在清单与说明里，按身份生成的只读导出视图留待以后。
3. **清单摘要只覆盖冻结内容**（`manifest_digest` = content 的 RFC 8785 规范化摘要），不含台账分配的版本 ID 与号码，因此可以在 `Prepare` 之前冻结；清单文件另带身份字段，读取时逐项核对。
4. **上传会话是提交操作的 receiving 阶段**：会话分配（由回执操作派生的）`operation_id`，复用授权只对该操作有效，安装在记录事务中复核并消费授权。完整上传才能取得 `uploaded` 授权；复用已提交版本的文件用 `authorized_source` 授权，逐来源判定许可。
5. **安装以私有安装区组装、整体改名落位**，目录内的标记记录所属操作与请求摘要，崩溃后重入只接管自己的目录；不把一次改名当作三平台的断电原子性，可见性由台账 `committed` 决定。硬链接去重，不支持时复制并重新核验。
6. **读取授权以 runtime.db 记录为准，HMAC 签名只作纵深防御**；每个 GET/Range 都经身份模块的 `BeginRead` 复核当前权限，并核对本人会话、台账已提交状态与用途限制。
7. **说明修订文件按修订号与操作命名**（`.rNNNNNN.<operation_id>.yaml`），被取消的尝试不会与之后的修订冲突；台账记录（修订号, 操作, 摘要）决定哪个文件生效，catalog 实现 `RevisionVerifier`。修订内容不含时间戳，同一请求重试得到相同字节与摘要。
8. **别名历史每代一个不可变文件，当前代次问台账**：路径是否被复用由占名的代次回答，只有解析旧代次时才读历史文件并核对资产已提交；历史文件可按台账补齐。
9. **入藏请求摘要按声明形式计算，冻结内容按操作暂存**：浮动引用在崩溃重试之间变化时仍还原 prepared 时的内容，同一幂等键不会因为解析结果不同而冲突或产生第二个版本。
10. **传输准入按可信档位分两个互不借用的并发池**，批量档先按主体排队再进全局池，带宽按虚拟调度限速并在有交互流量时让出。

## 后果

- T03 实现台账时直接实现这些接口并通过契约套件；catalog 与 storage 不需要改动调用方式。`asset.*` 等由 catalog 定义、需要随台账事务写出的事件，届时由台账在同一事务写入 outbox。
- 数据目录不是按人读路径组织的；需要直接浏览时由将来的导出视图生成，且只含已提交、获授权的内容。
- 冻结内容、隔离区与孤立目录需要运维清理与对账（GC 与 fsck 属 M2/T08）；本轮只提供只读扫描与按操作隔离。
