# 第一次设置管理员：从引导码到动态验证码

适用版本：`v0.1.0-rc.2`，运行代码 `676de7aa5777e6e71e10d68ef98331b87776b8b8`。文档修订：2026-10-11。本文面向已经启动单 Compose 项目的使用者，不要求再次部署。

**已经完成初始化的实例，到这里就可以停下：**正常服务的 `/api/v1/meta` 返回 HTTP 200，`/setup/` 返回 HTTP 404。根路径 `/` 返回 404 也正常；rc2 没有完整业务首页。不要为重新打开设置页而重装、删卷或重新初始化。

## 先准备好，再按“继续”

在可信电脑上准备浏览器、密码管理器或手机验证器，以及保存恢复码的安全位置。先看完第 3 步中自己要用的验证器路线，再进入第二屏；第二屏只有 10 分钟有效期。

全文示例都是假数据：示例网址 `https://library.example:32444`、用户名 `ada`、动态码 `123456`，以及尖括号里的占位内容都不能直接用于自己的实例。实际网址用交付 README 指定的域名和端口，不改为 IP，不忽略证书警告。

## 这五种东西各填在哪里

| 名称 | 谁产生、在哪里出现 | 填写位置 | 如何保留 |
|---|---|---|---|
| setup 引导码 | Lantai 首次启动产生；部署目录 `setup/setup-code.json` 的 `code` 字段（以实际挂载为准） | 浏览器 `/setup/` 第一屏“引导码” | 仅供本次初始化；未完成时原码可继续用。成功后失效，残留文件也不能重开设置 |
| 管理员密码（页面叫“口令”） | 你自己或可信密码管理器生成，至少 12 个字符 | 第一屏“口令”与“再次输入口令” | 存入密码管理器的 Lantai 账户，供以后登录 |
| TOTP 设置密钥 | 按“继续”后由 Lantai 产生；第二屏说明文字下面的长串字符 | **验证器应用**的“设置密钥”或对应手动密钥栏 | 保存在验证器的 Lantai 条目内；它能持续生成动态码，应当像密码一样保护 |
| 6 位动态验证码 | 验证器根据 TOTP 密钥和当前时间生成，通常每 30 秒变化 | 浏览器第二屏“验证器当前 6 位动态码” | 临时使用，无需抄存；过期就取下一组，开头的 0 也要保留 |
| 恢复码 | Lantai 第二屏长串密钥下面的一整组多行内容 | 本步骤**不用填入**动态码栏；保存后勾选“我已安全保存这些恢复码” | 全部保存到可信密码管理器的受保护备注或离线安全位置；每个只能用一次，完成后不能再次查看 |

“验证器”是 Mac 的“密码”、Google Authenticator 或 Microsoft Authenticator 等应用。它不会替你生成管理员密码或 setup 引导码。**长串 TOTP 设置密钥、引导码和恢复码都不是 6 位动态码。**恢复码用于后续受限恢复流程，不是普通登录验证码；不要为测试恢复码而启动恢复操作。

## 第 1 步：找到引导码，再打开设置页

1. **在 NAS 的容器管理器里**找到本次 Compose 项目，查看 `core` 的目录挂载。容器目标 `/var/lib/lantai-setup` 对应的宿主目录就是需要查看的位置。当前 GUI 交付包默认为项目旁边的 `./setup`；从该项目目录看，文件路径是 `setup/setup-code.json`。这是独立的 setup 挂载，**不要去数据命名卷的 `db/` 或密钥卷里找**。修改过 `LANTAI_SETUP_DIR` 时，以实际挂载为准。
2. **在 NAS 的文件管理器里**打开上述宿主目录。如果你的管理员身份能打开 `setup-code.json`，只复制 JSON 的 `code` 字段值，不要复制字段名、引号、整个 JSON 或 `instance_id`。
3. **如果 GUI 显示拒绝访问或不能预览文件：**这不等于文件未生成。目录权限为 `0700`、文件 `0600`，属服务 UID/GID `65532:65532`；不同 NAS 的 GUI 是否能以特权读取，需要实机确认，本指南不保证能读。使用你**已经配置并授权**的宿主管理终端/SSH，或厂商明确支持的特权文件读取工具。没有这样的通道时，由设备管理员提供读取方式，先不要按“继续”。
4. 只有在已有宿主管理终端、当前账户具备 sudo 权限，且已经确认实际宿主路径时，才可用下面的只读示例。把占位路径换成上一步查到的路径；输出只留在可信本地终端，由你取出 `code`，不要上传截图或终端记录：

   ```sh
   sudo cat '/实际宿主项目绝对路径/setup/setup-code.json'
   ```

   已是 root 的管理终端可用 `cat`。这不是让你新开 SSH 或在容器里找 shell：rc2 核心镜像没有 shell、`cat` 或 Python。不要执行 `chmod`/`chown` 放宽权限，不要把文件复制到公开共享区，也不要让引导码进入聊天、日志或网址。
5. **在电脑浏览器地址栏**输入交付 README 中的 HTTPS 地址，末尾加 `/setup/`（假例：`https://library.example:32444/setup/`）。下一步应看到标题“设置 Lantai 管理员”及“引导码”“管理员用户名”“口令”“再次输入口令”。若已是 404，先按[状态判断](#状态判断先区分过期与已经完成)核实，不要重置。

## 第 2 步：填写第一屏

1. **浏览器“引导码”**：粘贴刚才 JSON 中 `code` 的值。
2. **“管理员用户名”**：自己选择，例如假例 `ada`；只用小写字母、数字、下划线或连字符，长度 1–32。
3. **“口令”和“再次输入口令”**：填同一份至少 12 个字符的新密码。先在可信密码管理器中保存好这个账户；它与 Mac 解锁密码、NAS 管理员密码都没有关系。
4. **点击“继续”**。成功后第一屏隐藏，出现“保存恢复码并设置验证器”：上方一串 TOTP 设置密钥，下方多行恢复码，再下方是保存确认勾选框和动态码输入框。此时开始约 10 分钟计时，第一屏密码和引导码输入框已被清空，这是预期行为。

**rc2 页面没有二维码。**请用下面的手动添加方式，不要寻找扫码按钮，也不要把密钥粘到在线二维码或验证码生成网站。

## 第 3 步：让验证器显示 6 位码（三选一）

### A. Mac 自带“密码” App

先在“密码”里建好 Lantai 账户，再给这个账户添加验证码。浏览器第二屏保持打开。

1. **Mac 上打开“密码” App**，按系统要求解锁。若还没有 Lantai 条目，先点边栏“全部”，再点“新建密码”（“+”）建立账户：网站填自己的 Lantai 地址，用户名和密码填第 2 步那一组，点击“保存”。已有条目就选中它，不要再建同名条目。
2. **在“密码”里选中 Lantai 账户，点击“编辑”**。只读详情页不是设置页；如果只看到网站、用户名和密码却找不到验证码入口，先进入“编辑”。
3. **点击“设置验证码”**，在“设置密钥”输入框粘贴**浏览器第二屏上方的长串 TOTP 密钥**。不要填 setup 引导码、管理员密码或恢复码。
4. **点击“使用设置密钥”**。若仍处于编辑状态或显示“保存以查看验证码”，继续点“保存”，回到该账户详情。这个提示是在要求保存刚才的密钥，不是要重新生成一份。
5. **在账户详情里找到“验证码”并点击复制**。现在应该是会变化的 6 位数字，而不是长串密钥。回到浏览器第二屏，按第 4 步完成。

新建条目见 [Apple 创建密码指南](https://support.apple.com/zh-hans/guide/passwords/mchla6acb8cb/mac)；“编辑 → 设置验证码 → 设置密钥 → 使用设置密钥”来自 [Apple 验证码指南](https://support.apple.com/zh-hans/guide/passwords/mchl873a6e72/mac)。“保存以查看验证码”的分支对应本次用户遇到的编辑状态。系统版本的布局可能不同，不能把只读详情页当作编辑页。本文未读取或操作任何人的“密码”条目。

### B. 手机 Microsoft Authenticator

从 [Microsoft 官方下载入口](https://www.microsoft.com/security/mobile-authenticator-app)进入 App Store / Google Play，确认发布者为 Microsoft；已安装可直接打开。[官方添加账户说明](https://support.microsoft.com/en-us/authenticator/how-to-add-your-accounts-to-microsoft-authenticator)核对了以下菜单，具体中文翻译随版本不同。

1. **手机打开 Microsoft Authenticator**，点顶部“+”添加账户；在账户类型页选 **Other account / 其他账户**。Lantai 属于第三方 TOTP 账户，不选 Microsoft 个人或工作/学校登录。
2. 在扫码界面选择 **Enter code manually / 手动输入代码**。Lantai 没有二维码，无需扫描电脑屏幕。
3. 在手动添加页填账户名称（如假例 `Lantai ada`），密钥填浏览器第二屏的长串 TOTP 密钥；若有类型选择，选基于时间的 TOTP，然后使用该页的完成/保存按钮。
4. 下一步回到账户列表，打开新建的 Lantai 条目，取其当前 **6 位验证码**，回电脑浏览器执行第 4 步。若安装版本没有手动输入入口，使用上面的 Mac 路线，不要把 Lantai 密钥填到要求 Microsoft 登录信息或激活 URL 的表单。

### C. 手机 Google Authenticator

官方入口：[Google 帮助（Android，含下载链接）](https://support.google.com/accounts/answer/1066447?hl=zh-Hans&co=GENIE.Platform%3DAndroid)、[Google 帮助（iPhone/iPad，含下载链接）](https://support.google.com/accounts/answer/1066447?hl=zh-Hans&co=GENIE.Platform%3DiOS)。确认应用发布者为 Google。

Google 官方帮助确认它可为第三方服务生成验证码，但本次查到的帮助页没有给出当前各版本手动添加的完整菜单。因此这里不编写未经核实的逐按钮路线。**若应用已有手动输入设置密钥入口**，账户名称填自己的 Lantai 标签、密钥填第二屏长串、类型选基于时间的 TOTP，保存后取 Lantai 的 6 位码；若找不到，请直接用 A 或 B。不要转到 Google 账号“两步验证”网页重设 Google 账户，那不是 Lantai 设置。

## 第 4 步：保存恢复码，回浏览器确认

1. **浏览器第二屏**：将长串 TOTP 密钥下方的**全部多行恢复码**保存到可信密码管理器的受保护备注，或离线安全位置。重新打开你保存的位置，确认整组内容完整。不要只保存其中一条，也不要用截图发给别人代存。
2. **仍在浏览器第二屏**：勾选“我已安全保存这些恢复码”。
3. **打开验证器的 Lantai 条目**：取当前 6 位码，填浏览器“验证器当前 6 位动态码”。快换码时等下一组再填；不要混入空格，不要丢掉开头的 0。
4. **点击“完成设置”**。成功后看到“管理员已建立”“服务正在启动”和“查看服务状态”。保留密码管理器里的密码、TOTP 条目及这组恢复码。
5. **点击“查看服务状态”**，或在地址栏访问同域名的 `/api/v1/meta`。正常会看到 JSON，HTTP 状态为 200。稍后重新访问 `/setup/` 返回 404，说明初始化入口已经关闭。不要因为浏览器根路径 `/` 是 404 而重装。

## 状态判断：先区分过期与已经完成

| 你看到什么 | 含义与下一步 |
|---|---|
| `Enrollment expired; start again` | 这次内存登记已过期/失效（也可能已达 5 次验证码尝试），不是要求重装。按下面的“重新登记”处理 |
| `Wait before restarting setup` | 距上次开始太近；等至少约 10 秒再按一次“继续”，不要连续点击 |
| `Verification failed` | 先确认使用的是本次 Lantai 条目的新码、设备自动时间正确、没有用旧密钥。若达 5 次或过期，重新登记；不要无限重试 |
| “保存以查看验证码” | 这是 Mac“密码”的编辑状态；在该 App 保存后看账户详情的 6 位码 |
| `Invalid setup code` | 核对是否只复制了本实例 `code` 字段；不要自己生成引导码或使用其他实例的码 |
| 点“完成设置”后断线、卡住或报网络错误 | **先保留本次密码、TOTP 和恢复码**。确认请求可能已提交；先按下面“结果不确定”检查，不要立刻重新开始 |
| `Administrator saved; restart the service to retry activation. Keep your recovery codes.` | 管理员已经写入，不能重新注册。保留原密码、TOTP、恢复码；交设备管理员按已有运维流程核查激活/重启同一实例。不要换卷或恢复出厂 |
| `/api/v1/meta` 为 200，同时 `/setup/` 为 404 | 正常服务已启动，首次设置已关闭，保留已保存凭据即可 |
| 只有 `/setup/` 为 404，但 meta 未恢复 | 404 单独不能证明服务全部正常。可能管理员已提交、激活尚未完成；保留凭据，查既有服务状态，不重置 |

### 重新登记（仅限尚未完成设置）

1. **浏览器**刷新同一个 `/setup/` 地址，重新看到第一屏。若是 404，停下，改按下节检查。
2. 使用**原 setup 引导码**重新填写第一屏。10 分钟失效的是第二屏这次登记，不是引导码。必要时等待约 10 秒再点击“继续”。
3. 第二屏会生成**新的 TOTP 设置密钥和新的整组恢复码**。把验证器里那份**未完成登记**的旧 Lantai 密钥替换为新密钥；保存新的全部恢复码并替换旧草稿。核对后不再使用旧码。若不确定旧登记是否已经提交，先查状态，不删除已有有效账户资料。
4. 使用新密钥产生的当前 6 位码完成确认。这个过程不需要重装、删数据/密钥卷、重启服务或删除 `setup-code.json`。

### 结果不确定（点击“完成设置”后连接中断）

先在另一个浏览器标签访问同域名 `/api/v1/meta`，给服务短暂启动时间，再查看 `/setup/`：

- meta 200 且 setup 404：已经完成，继续使用刚才保存的那组凭据。
- setup 仍能返回第一屏：确认网络/地址正确，并保留上一组材料，按“重新登记”继续。
- setup 404，但 meta 连接失败/5xx，或出现 `Administrator saved`：可能已写入管理员，交管理员查同一项目的 `core`/`gateway` 状态和不含秘密的错误信息；不要试图让初始化重新开放。

不要删除数据库、密钥、卷或执行 `docker compose down -v`；这些动作不是过期或网络错误的解决方法。域名、证书和代理 FakeIP 问题应转查交付 README 指向的既有网络说明，保留当前凭据，不在本指南中变更生产配置。

可选：熟悉终端的使用者可以在**自己的电脑**用下面的只读命令只看 HTTP 状态，把假域名替换成实际地址；不加 `-k`、不带任何密钥，网络/TLS 失败不能当作“需要初始化”：

```sh
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' 'https://library.example:32444/api/v1/meta'
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' 'https://library.example:32444/setup/'
```
