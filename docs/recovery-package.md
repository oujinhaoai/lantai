# 自包含恢复包

本次开发替代独立恢复口令方案；不是已发布 rc.6 的能力。页面、管理 API、每日计划和本机命令使用同一个 core 备份协调器。默认成功产物必须包含完整快照与匹配的恢复密钥材料，新目标不依赖原 NAS、另行复制的 `master.key` 或独立恢复口令。

## 安全模型

恢复包是敏感的持有者能力。能够读取完整包的人能够读取其中数据和恢复材料；不声称同包加密能防持包者读取，也不把自带公钥或自带摘要称为可信来源认证。内置 SHA-256 只检查完整性和文件绑定，不能防止能重写整个包的攻击者伪造新包。恢复前由用户确认来源、捕获点和目标；有独立可信摘要时可额外核对。

core 输出目录必须保持原备份根身份、服务属主、0700 目录与0600文件约束。页面/API下载要求当前人类管理员、admin scope和新鲜敏感授权；维护控制身份、Agent、委托会话无下载权限。下载不用长效公开链接或URL秘密。浏览器接收包后，用户须按敏感资料保护它；不要求保存额外恢复口令。

## 容器与状态

`lantai.recovery-package/v1` 是无压缩、有界流式容器：固定 magic、长度受限的清单、按清单顺序的文件字节和整包SHA-256尾部。清单绑定实例、备份、捕获时间、恢复代际、密钥ID、原数据清单摘要、全部文件的相对路径/长度/摘要。恢复密钥条目只存在于完整敏感包中，不写入普通v1数据快照；也没有裸密钥HTTP接口。

四个权威数据库、CAS、可变文件和现有快照清单继续用 `lantai.backup/v1` 的白名单及正式校验器验证；索引恢复后重建。旧v1数据快照明确标为“缺少独立恢复材料”，不能冒充新完整包；只有仍持有匹配密钥的core才可重新导出。

任务依次执行排空、捕获/复制、快照校验、完整封包、整包回读校验和原子发布。全部成功且持久回执落盘才报告可恢复完成。失败/取消仍等待worker退出再恢复业务；重启只允许同一捕获点重试。新格式无加密nonce或口令状态，不引入加密续写风险。

Linux/macOS 的完整包以同目录、不可覆盖的原子重命名发布，不再以临时文件硬链接发布；文件系统不支持此操作时明确失败，不退回覆盖写入。目录同步后重新打开最终文件，复验普通文件、服务属主、0600、单一硬链接、文件身份和完整内容；在线任务落盘 `complete` 前再次核对包与任务绑定。已有包的续传同样复验并补做目录同步，不自动删除未知链接或替换不同的包。其他平台保留原独占发布方式及各自的私有访问检查，须单独实测。

`complete` 是当时生成和验证成功的历史记录，不保证文件此后未被外部修改。每次下载仍按同一安全条件检查，并将实际包 ID、备份 ID、大小和 SHA-256 与原完成记录匹配。`STORAGE_UNAVAILABLE` 的 `details.reason` 可区分 `backup_package_hardlinks`（硬链接计数异常）、`backup_package_permissions`、`backup_package_owner`、`backup_package_file_type`、`backup_package_path_unsafe`、`backup_package_changed`、`backup_package_integrity`、`backup_package_identity` 和 `backup_package_unavailable`；目录故障保持 `backup_unavailable`。计数异常本身不能证明实际第二链接或文件系统报告差异的来源；保留原包和现场元数据再调查，不放宽权限或删除未知目录项。

## 恢复

新目标先完成自己的安装认领，不能凭首次访问抢占；不接受覆盖已有业务数据。上传只写私有隔离区，并执行长度/数量/路径/重复项/完整性/数据库/密钥绑定与兼容性检查。没有任意宿主路径API。

core在内存获得包中旧密钥并复用正式恢复：旧因子核验、恢复代际提升、全部旧身份失效、新运行主密钥、新管理员确认及对账门禁。恢复材料不被直接安装为新运行密钥。所有后台执行和计划默认关闭。UI展示自动检查及仍需确认的灾后未知事项，不用任意三个true替代对账证明。

## 必须验证

- 页面/API/每日计划各自生成单包，独立校验相同完整性语义；原core离线后，仅用单包完成新目标恢复。
- 普通身份、Agent、委托、撤权、过期会话、维护控制身份均不能导出；下载断点、并发和制品替换不会串包。
- 错密钥绑定、缺材料、截断、尾随数据、非法/重复路径、大小上限、空间不足、EIO、取消和重启均失败关闭。
- 新目标认领、旧身份失效、新密钥、管理员重建和对账每一持久边界中断后仍保持门禁。
- 使用合成资料进行Linux/amd64和Darwin/arm64隔离验证；不接触真实密钥、NAS或现用部署，不发布新版本。

## 交付与容量

固定产物为 `<备份根>/<job_id>/recovery.lantai`。文件和内层快照合计约占两份数据，预检再保留临时开销和配置的最低剩余空间。取消或失败会清理未发布的临时包；底层存储拒绝清理时残留仍受私有权限保护，不记成功；已完成文件原子发布并逐字节回读验证，重试不能覆盖已有不同包。

新目标上传和解包使用其私有 setup 挂载，不依赖可写容器根目录，也不把整包放进 `/tmp`。数据卷和 setup 卷均须有足够空间。原实例的配额、上传到期、传输限速/并发、HTTP 大小/超时和生命周期批量参数会保留。新目标配置只决定监听、Origin、密钥目录与 FUSE 准入；包中的旧宿主路径不生效。生命周期自动调度强制关闭，原备份计划不复活。

本机 `backup`（包含 `-before-upgrade`）、在线命令、页面/API、每日计划都使用同一完整打包实现。`backup-verify` 接受单文件，旧目录形式仅校验旧数据快照。新目标向导无需手工编写对账 JSON；它生成受本次恢复绑定的 v2 接受记录。历史 v1 手动恢复接口保持兼容。

## 配置恢复规则

| 字段 | 恢复行为 |
|---|---|
| `instance.name`、`storage.min_free_bytes`、文件/上传总量/数量配额、上传到期 | 保留备份原值；缺省字段继续使用该版本默认值。 |
| `http.max_json_bytes`、`http.api_timeout_seconds`、`transfer.*` | 保留原值，不被新空实例的默认配置覆盖。 |
| `lifecycle.interval_seconds`、`lifecycle.batch` | 保留原值。 |
| `secrets.dir`、`listen.*`、`http.allowed_origins` | 使用新目标明确配置；缺省时采用本机安全默认值，不启用旧主机地址。 |
| `storage.allow_fuse` | 作为目标文件系统准入策略重新绑定，默认 false；旧主机的 FUSE 许可不能自动授权新主机。 |
| `lifecycle.scheduler`、备份计划 | 停用，使用新管理员后显式重新启用。 |
| 项目配置、配置类素材及其历史版本 | 按原权威记录与字节恢复。 |
