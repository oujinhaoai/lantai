# 五入口操作指南

先完成[开始前检查](acceptance.md#开始前)与[创建项目和权限](accounts.md)。以下每个入口都给出用途、前提、按钮路径、合成示例、操作步骤、成功标准、失败处理和证据。仅在批准的合成项目中执行；已实现的页面不代表所有业务分支或 NAS 现场已经通过验收。

## 素材库

**用途：**查找当前有权读取的素材、固定版本与文件，编辑获准的当前著录。**前提：**项目读取角色及 read；编辑本人素材还需适用角色、organize 与当前标签页登录校验。**按钮路径：**侧栏“素材库”→选项目/筛选→素材详情。**填写示例：**查找本次合成 sample.txt 对应素材；摘要改为“人工验收合成备注”，不用真实路径。

1. 选择已授权项目，按类型、关键词或精确标签查询。有下一页时继续读取，不把第一页或空页当作全部资料。
2. 打开素材，记录 asset_id、固定 version_id。展开“查看文件清单与 SHA-256”，核对 sample.txt 的路径、大小与摘要。
3. 选文件，点“预览文件”。下载时先点“申请下载原文件”，再点“下载原文件”；等待实际完成，用本机工具比较下载文件与源文件的大小和完整 SHA-256。
4. 按权限展开“编辑当前素材信息”，修改摘要，点“保存当前著录”。重新打开同一资产，核对新摘要与著录修订。需要画像时明确启用“编辑结构化画像（保留未知 extra）”，填写角色、来源、描述性业务状态、旧状态/版本、来源路径与备注。
5. 当前用途另在“固定版本用途与 rights 管理”点击“读取当前权利与用途”。普通画像、标签或“已通过”文字不会授予 production、导出或发布权；真实证据更正/解除另需对应领域权限与动作确认。

**成功标准：**固定版本文件的实际下载字节与源一致；当前著录修改可重读，著录 revision 增加而原文件 version_id 未改变。**失败处理：**摘要不符、权限拒绝、修订冲突或不支持的预览先停止，保留草稿和原请求；不覆盖他人著录、不重传代替待补说明。**证据：**筛选范围、asset/version、清单及实际下载大小/SHA、著录前后 revision、脱敏截图。点击下载或预览成功不能单独写为字节完整。

## 迁移中心

**用途：**把明确选中的合成资料复制入藏，保留原状态、逐项回执及核验结果。**前提：**contributor 等适用项目角色，read/ingest；完善本人素材初始著录还需 organize 与当前标签页校验。**按钮路径：**侧栏“迁移中心”。**填写示例：**批次“合成小批次”，来源别名“合成输入”，一份自己创建的 sample.txt；分组 key=`sample-group`，新资产路径名=`manual/sample`，标题“合成验收文本”，分类“最终资料”，用途 reference，许可证 `LicenseRef-Synthetic-Acceptance`。这些条款只用于本人合成文件，不能照抄给真实资料。

1. 在“1. 来源与目标”选择目标项目，点“选择明确文件”。展开“来源清单与分组选择”，勾选本次 sample.txt，核对相对路径与文件角色；未选内容没有被盘点。
2. 填写稳定分组 key、分类、素材类型、路径名、标题及明确 rights。点“把所选 1 个文件加入明确分组”，审阅分组/项目映射、原件范围、权利、排除/未知项及容量。未知容量仍保持未知；声明不足时不要冻结。
3. 勾选审阅与保留源文件责任，点“冻结明确计划并生成原操作状态（尚不写入）”。点“下载最新原状态与计划”，实际保存后再勾选“我已实际保存原状态；断线和补著录只用原键”。
4. 点“按原计划／原键执行或续办”。逐项核对 committed、description_pending、failed、unknown、not_attempted；保留所有计划行，不移除失败和未知来制造完成。
5. 有固定回执后点“重新核验当前远端全部固定文件”，等待完整下载 SHA 检查。需要台账时点“从当前明确批次建立台账”，核对责任人、全部导入统计和固定证据；保存台账前按页面要求保存原状态。

**成功标准：**本次明确范围全部有对应回执，当前完整文件核验通过，台账统计覆盖全部计划行。入藏与文件核验不是整个批次 ready；缺原生续做、设备作业或恢复证据仍可能 blocked/unknown。**失败处理：**保留源件、原批次、原状态和键，先对账；不把取消当回滚，不换键重传。**证据：**来源范围、计划摘要、原状态私有保存位置、每行结果、asset/version/operation、完整 SHA 与台账修订。真实设备与 M1-07 改链/rollback 须单独安排，不在普通浏览器中猜测本机目录或代替助手执行。

## 工程工作集

**用途：**把固定素材版本组成明确工作副本，并保存/重开馆内档案。**前提：**引用素材可读；保存 config 档案需目标项目 ingest，初始著录需 organize。**按钮路径：**侧栏“工程工作集”。**填写示例：**名称“合成固定工作集”，资产/版本 ID 从 sample.txt 真实回执复制，独占相对目录 `sample`，入口文件 `sample/sample.txt`，显式依赖 `[]`，读取用途“档案查看”。

1. 点“添加固定版本”，填写资产 ID、固定版本 ID、独占相对目录，核对入口与依赖。点“检查当前固定清单与依赖”，等待“本次远端核验”的文件数、大小、SHA 和工作集摘要。
2. 选择实际读取用途，点“拉取并校验 TAR”。等待文件真正下载，解到新的合成目录，比较其中 sample.txt 与原件的大小及完整 SHA-256。不能把 TAR 按钮点击或包存在当作所有文件正确。
3. 在“5. 保存／打开馆内工作集记录”填写“归档项目 ID”，确认有权保存并采用私人记录条款。点“准备档案及原状态”，下载并实际保存“最新原操作状态”，再勾选已保存并点“保存记录”。
4. 保存后记录“固定记录”的**档案自身** asset_id/version_id。显式点“读取项目工作集记录”；索引尚未追平时，稍后再次点同一查询。从返回列表点这份工作集，核对“已重新核对当前远端”的提示和固定清单。仅打开还保留在内存的草稿不算重开。
5. 回交新字节时使用“回交新的素材版本”，明确原条目/固定基线、完整文件与权利，保存原状态后提交；如需采用新版本，再明确创建工作集修订。此分支须另做人工用例，旧工作集不会自动跟随最新版。

**成功标准：**固定输入、实际 TAR 内字节和重新打开的档案一致；列表发现与档案重读分别通过。**失败处理：**路径冲突、依赖缺失、权限/用途拒绝、stale base 或列表持续找不到时停止，保留原状态；固定 ID 后备打开成功不能覆盖列表发现失败。**证据：**输入摘要、引用的 asset/version、目标路径、实际解出字节摘要、档案自身身份和列表重开结果。本机磁盘冲突、Blender/ComfyUI 等实际打开编辑未做就填未测。

## 备份与恢复

**用途：**由管理员在批准窗口建立完整保护点，分别核对备份与恢复。**前提：**本人系统管理员、明确选择管理员登录；备份目录由设备管理员预先配置且页面显示可用，已有业务已协调暂停。**按钮路径：**侧栏“备份与恢复”→“备份管理”。**填写示例：**使用专用合成实例中的当前资料；不把真实 NAS 路径或凭据填进验收模板。

1. 读取“备份目录”“当前任务”和“上次成功”，确认目录状态；不可用时由设备管理员修复挂载/权限/容量，普通用户不修改服务卷。
2. 点“立即备份”，核对服务器给出的暂停说明和完整目标，输入新的“确认操作的验证器动态码”，点“验证并执行”。备份期间正常业务读写会暂停。
3. 等状态为“已完成并验证”，核对完整恢复包大小与 SHA-256。需要下载时点“下载完整恢复包”，再次完成对应确认，实际保存并核对大小/摘要，私密保管这个具有恢复能力的包。
4. 记录任务标识 job.id 与另一个备份标识 backup_id。需要升级备份目录时，由管理员按原备份宿主目录加完整任务 job.id 定位直接含 manifest.json 的目录，不能混用这两个 ID。
5. 在另一条独立用例中安排兼容版本、隔离空目标的恢复；完整包生成不等于新目标已恢复。步骤与边界见[备份与恢复](backup.md)。

**成功标准：**本次备份确实完成并验证；下载验收还需实际字节校验。恢复一项只有在独立目标完成管理员因素、恢复接受、历史版本重读和重启后才能判断。**失败处理：**失败、取消、interrupted 或状态不明保留原任务，先修复并沿同一任务“续传此任务”；取消须等实际退出，不手工伪造完成。**证据：**job.id、backup_id、捕获时间、包大小/摘要、当前任务终态；不把包本体、恢复码或私钥附到公开记录。旧版纯 GUI 恢复缺口及禁止同卷换旧镜像降级见[恢复边界](backup.md#恢复验收的边界)。

## 系统管理

**用途：**由有权人管理项目、明确成员与敏感动作。**前提：**本人普通浏览器会话、管理员范围和相应系统/项目权限；管理员不会自动成为项目 owner。**按钮路径：**侧栏“系统管理”→“项目与成员权限”；其他分区为“主体与凭据”“协作、审定与回收”“项目审计”“设备与本机执行”。**填写示例：**项目 key=`manual-check-demo`，类别“合成试验”；主体 ID 与项目 ID 从实际回执核对，不在公开手册预填个人 ID。

1. 按[创建项目与阅读回执](accounts.md#创建项目与阅读回执)核对请求并创建，记录 project_id、created_by、说明修订与 pending/error。先保存原请求诊断，结果不明不重复创建。
2. 在“成员管理的明确项目标识”填回执 ID，点“读取此项目成员”。不要因“已授权项目”下拉中找不到它而阻塞这条明确 ID 查询。
3. 按职责选 viewer 或 contributor 等角色，点“请求动作绑定的人类确认”。核对动作/目标/修订，用新的动态码“验证并执行”，再“读取当前成员修订”核对结果。
4. 本人重新进入“我的项目”，检查实际可见范围；需要写入时重新明确选择素材写入与整理范围。协作审定、发布、回收或设备批准各有独立动作，不把项目创建或管理员登录当成全部批准。

**成功标准：**创建事实、说明结果、成员变更与实际访问一致；读取权限与写入范围分别满足。**失败处理：**修订冲突、过期、撤权或丢响应保持原请求/键先对账；一次性秘密丢失由受控吊销重发处理，不在诊断或截图中回显。**证据：**脱敏的创建回执、最新成员修订、本人可访问项目、敏感操作结果与错误码。设备作业、所有审定/发布分支和真实生产权限仍须各自验收。

## 汇总与停止

用[空白验收记录](acceptance.md#空白验收记录)为每一项填写预期、实际、证据和通过/失败/未测/阻塞。发生 TLS、实例、权限、修订、摘要、恢复或未知副作用问题时，按[停止条件](acceptance.md#常见问题与停止条件)停在原状态，不删卷、删锁、换键或伪造通过。
