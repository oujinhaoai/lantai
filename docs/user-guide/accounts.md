# 创建项目与权限

目标：在网页创建一个合成项目，读懂服务器回执，再按职责分配访问权限。适用于 r10 核心与兼容管理网页；历史 rc.4 没有这些管理页面。先读本页，再到[五入口操作](admin.md)，无需先运行 CLI。

## 登录与会话范围

1. 在原 HTTPS 根页输入自己的“账户名称”“口令”“验证器动态码”。动态码只填登录框，不写入记录或截图。
2. 普通查看直接点“登录并浏览”，本次只申请 self/read。
3. 需要合成文件入藏或编辑时，明确勾选“素材写入与整理（迁移、工作集档案和信息编辑）”，本次另申请 ingest/organize。
4. 获准的系统管理员进行项目、成员或整馆备份管理时，再勾选“管理员登录（含备份管理权限）”。创建项目时若要同时写入名称、类别和说明，也应选择写入与整理范围。
5. 点击“登录并浏览”，确认首页问候的是本人。已登录的会话不会因后来分配角色而自动增加 scope；需要额外范围时退出后重新明确选择。

项目角色决定这个人在项目里可做什么；会话范围只收窄当前登录可用的能力。**有角色仍需本次会话的写入范围；勾选写入范围也不会自动授予项目角色。** 不建议为排障直接把所有人升为 owner。

## 创建项目与阅读回执

前提：本人具有系统管理员角色和相应会话范围。路径为“系统管理”→“项目与成员权限”→“创建项目”。

1. 填入合成示例：“项目 key”=`manual-check-demo`，“名称”=`人工验收示例`，“项目类别”选择“合成试验”，“说明”填“仅用于合成验收”。示例 key 已存在时，先核对原回执，不把重名失败当作需要重复创建的理由。
2. 点“核对创建请求”，在确认框核对 key、名称、类别和说明。可先“保存原请求诊断”到自己的私有验收目录，保留原请求和键。
3. 点“确认执行”。展开“服务器操作回执”，按下表读取结果；按钮点击或确认框关闭本身不是成功证据。

| 回执内容 | 应核对什么 |
| --- | --- |
| project_id | 服务器返回的稳定项目标识。复制它用于成员查询；项目名称、key 都不能替代它 |
| created_by | 创建者主体标识，应对应本次本人；它证明创建事实，不证明已经获得项目资料角色 |
| operation_id | 保存供原操作对账，不凭名字猜测项目是否已创建 |
| description.revision | 已生效的项目说明修订；名称、类别和说明要与请求相符 |
| description_pending | 为 true 时，项目已经登记，但说明未完整生效；不能把它算作全部完成 |
| description_error／页面错误 | 原样记录错误码。字段未出现不等于可以忽略其他异常 |

`description_pending=true` 时保留同一 project_id、回执与原请求诊断，先核对 organize 范围和说明错误。当前界面若不能沿原请求安全续办，记录为“阻塞”并交给管理员处理；不要新建另一个项目来掩盖已登记结果，也不要虚构已补完的按钮。

## 创建后看不到项目

“我的项目”和素材列表按当前 ACL 过滤。**管理员创建项目后不自动获得该项目的资料读取角色。** 新项目可能已经创建成功，但尚不出现在资料列表；这不能单独证明创建失败或资料丢失。

保留创建回执，在同一“项目与成员权限”页找到“按明确项目标识管理成员”。在“成员管理的明确项目标识”粘贴服务器返回的 project_id，点“读取此项目成员”。这个查询只读取访问控制，不会替自己授予资料角色，也不要求先从“已授权项目”列表选中刚创建的项目。

## 读取成员并授予所需角色

1. 读取后核对“成员管理项目”和“访问控制修订”。刚创建且无成员的项目可能为修订0，应以实际返回值为准。
2. 在“主体标识”填写被授权人的真实主体 ID。已有成员可点“选择此主体”；新成员的 ID 应由管理员在“主体与凭据”核对，不能填账户名称、项目 ID 或猜出的标识。给本人授权时，可核对创建回执中的 created_by。
3. 根据工作选择“项目角色”，在“动作”选择“授予”。只验收读取可用 viewer；要入藏本人合成文件，可按职责用 contributor。
4. 点“请求动作绑定的人类确认”。核对服务器给出的动作、目标项目、主体、角色、授予/撤销及预期修订。
5. 在“确认操作的验证器动态码”填**新的**当前码，再点“验证并执行”。刚用于登录或其他成功操作的同一时间步不可重用，等待验证器换码；不关闭 TOTP。
6. 取得服务器回执后，点“读取当前成员修订”，核对指定主体、角色和修订已改变。回到“我的项目”显式重新读取；若会话缺范围，退出并重新登录。

| 角色 | 合成验收中的用途 | 不应推定的能力 |
| --- | --- | --- |
| viewer | 读取有权项目、固定素材及获准用途的文件 | 不具备文件入藏或著录写入权限 |
| contributor | 配合 read/ingest 提交自己的素材；organize 范围允许时维护自己素材的著录 | 不自动获得他人素材整理、项目成员管理、整馆备份或发布权限 |
| curator／其他职责角色 | 由项目负责人按实际工作授权，仍受动作与 scope 限制 | 不作为排障时的默认升级方案 |

不需要的授权由有权人选择“撤销”，再次核对动作并完成新鲜动态码确认；撤销后重读成员。只处理明确的测试授权，不更改真实项目权限。

## 失败时停止与证据

成功证据是项目创建回执、说明状态、指定项目的最新成员修订以及本人实际可访问范围。私有记录可保存对应 ID、时间和不含秘密的截图，不记录口令、动态码、恢复码、Cookie 或 HumanGrant。

发生修订冲突、过期/撤权、动态码错误或网络结果不明时，停止新的授权请求。保留原确认框、原操作和诊断，先核对已执行结果；页面提供“按原授权与键重试”或“按原请求和键重试”时仍须核对原目标。不要改角色、换键或再建项目来绕过失败。

Agent 登记、一次性秘密与因子恢复属于专门管理流程，不是普通验收前提。需要时由管理员参考[身份规则](../contracts/identity.md)；单一管理员丢失因素不能通过清空资料卷解决。
