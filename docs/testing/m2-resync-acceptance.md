# M2 增量重同步软件验收

本套件使用临时合成实例和真实 `application` 组装。代码见 [`m2_resync_acceptance_test.go`](../../tests/integration/m2_resync_acceptance_test.go)，沿用 T01/T02/T03/T04/T05/T06 的领域所有者，不替换任务、查询授权或事件服务。

在具备 Go 工具链、Python、进程启动与 loopback 监听权限的本机运行：

```sh
GOMAXPROCS=2 GOFLAGS=-p=2 go test -race -count=1 -run '^TestM2ResyncAcceptance' -v ./tests/integration
```

可选 `LANTAI_M207_EVIDENCE` 指向仓库外的空目录，保存每个用例的合成 REST 响应与观察值。文件以独占创建方式写入，重复运行须使用新目录；凭据签发和人因验证响应不进入记录。完整工程检查仍用 `scripts/check.sh`，保持默认 race 和 30 分钟单包预算；多个验收工作树的完整检查应串行执行。

## 验收边界

| 用例 | 实际检查 |
|---|---|
| `MilestoneREST` | 真实任务经 REST 建立、领取、交付、完成；里程碑创建、更新、回执重放、列表和 0/1 → 1/1 进度；条件修订与任务数组必填、负责人资格、权限、跨项目任务/里程碑、旧修订、异载荷复用 key 均拒绝。成功响应对照 OpenAPI。 |
| `DiscussionsAndInbox` | 四类讨论、幂等与异载荷冲突、跨对象回复拒绝；已读不改业务状态；人工答复重复投递保持一个历史记录，旧租约拒绝；改派前的收件箱即时失去相关性，成员撤权后旧会话的任务、讨论与收件箱读取拒绝。 |
| `RetainedConcurrentReplace` | 真实备份确认、审计导出和消费提交约束事件裁剪；保留窗口前不能裁剪，推进服务端时钟后正式裁剪并拒绝旧游标。REST 与独立 CLI 比较全过滤页水位、重同步分页和交叉续页；跨身份游标拒绝。 |
| `FixedContextAndDecision` | context 与 decision 各经真实任务、corecheck 一次性进程、独立质检和 HumanGrant 审定/发布，再分别替代。未批准候选不影响有效集合，新任务固定新集合，旧任务与创建 key 重放保持原精确版本及摘要；旧批准历史可读。 |

重同步用例先缓存含个人素材及其讨论的集合。客户端收到个人版本快照页后暂停，另一 goroutine 经真实接口完成改派、撤销 `personal.readers` 和新增任务，再继续分页。客户端收到第一张重放页后再次暂停，完成取消和另一新增任务，再应用已收到的页。每张事件页重投两次，以事件 ID 和对象修订去重；收到 `replace_required` 时丢弃累积集合，从新快照的 `replay_after` 继续。最终集合和水位必须与新鲜权威快照完全相同，撤权对象及其讨论消失，两阶段新增对象保留，取消与改派状态正确。

改派使任务离开旧身份的待处理收件箱；保留项目读取角色的身份仍可读取任务。个人素材撤权会从重同步集合移除其内容和讨论，精确版本读取返回 `NOT_FOUND`，讨论读取按现有内容权限返回 `USE_RESTRICTED`。

## 证据适用性

测试通过正式 `Events.Prune` 触发游标过期，不修改数据库事件时间；时钟推进不代表真实经过 90 天。客户端集合是遵守公开协议的测试参考实现，独立 CLI 负责协议比较，不代表已交付持久缓存产品或目标 MCP 客户端。

上下文用例的验收配置是既有预批准夹具；四份 context/decision 的任务、检查、质检、人审及发布均实际执行。本套件不替代首次配置审批专项验收。

软件通过不等于整卡独立评审、阶段门禁、目标设备/NAS/其他平台行为、持续 RPO 或 14 天长稳通过。实际版本、失败、二进制摘要和原始执行证据维护在维护者知识库，不在公开任务基线记录完成状态。
