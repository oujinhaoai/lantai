# T05 — 任务、租约与确定性业务流程

用途：**公开任务基线**。按子任务标注阶段验收，M1 完成不代表整卡完成。进度管理、共同规则与依赖见[任务总表](README.md)。

## 目标

用持久任务和固定流程完成“制作 → 检查 → 独立质检 → 人审 → 发布 → 下游取用”，支持至少一次返工、交接、取消及故障恢复。外层 Flow 只按定义和领域事实推进；任务内 Agent 的规划与工具执行由 T06 承接。

## 模块与数据归属

| 模块 | 唯一拥有的数据与职责 | 通过接口使用的能力 |
|---|---|---|
| `tasks` | `runtime.db` 中 Task、Seat、Attempt、任务租约、Checkout、指派、交接与任务转换；只有该模块创建或失效任务 `lease_fence` | T01 身份/能力授权，T03 资源锁与验收事实，T06 执行观察 |
| `workflow` | `runtime.db` 中 Flow、业务 StepRun、输入锁定、定义版本、待发命令与步骤转移去重 | T06 创建执行或作业，T03 请求审定/发布，T04 消费领域事件 |

每个模块只修改自己拥有的表。同库不意味着可以越过模块接口更新租约；业务变更、所属回执和 outbox 的事务边界沿用 T00/T04 契约。流程定义是版本化配置，实例钉住具体版本。

T05 不拥有 TaskRun、AgentStepRun 或后端执行映射；这些由 T06 管理并引用 `attempt_id`。审定结论、发布指针、生命周期和资源锁事实归 T03，身份与授权事实归 T01。

## 具体子任务

| 编号 | 阶段 | 工作与交付 |
|---|---|---|
| T05.1 | M1 契约预留；M2 实现 | 向 T00 提交 Task/Seat/Attempt/Flow/StepRun schema、状态表和错误码样例；定义 `operation_id`、`expected_revision`、`attempt_id`、`lease_fence`、`recovery_epoch` 的检查点。M1 不要求启用任务服务。 |
| T05.2 | M2 | 实现单席位创建、指派、原子领取、心跳、释放、超时、取消和条件交付；新一轮领取产生新 Attempt。把“旧执行权失效”和“安全可再次领取”分开，外部动作未确认停止时进入待对账。 |
| T05.3 | M2 | 实现二进制 exclusive、文档/config advisory 签出；领取/释放与 Checkout 对应，提交仍核验当前 lease、资源锁、权限和基线。候选组只能获得明确授权的例外，不能凭同一 Flow 绕过约束。 |
| T05.4 | M2 | 实现内置入库、新建、修改顺序流程；输入在开始时解析为固定版本。把制作、检查、质检、人审、发布建成明确步骤；按事件和条件更新推进，重复事件不重复创建任务或发起发布。 |
| T05.5 | M2 | 实现返工新轮次、结构化交接、阻塞/答复、暂停与取消传播；讨论记录经 T03 接口写入，固定项目上下文/决议版本由 T02 提供。答复只解除等待，不复活旧租约；依赖发布结果的步骤等待发布成功，不能把 approved 当 published。 |
| T05.6 | M3 后续 | 在固定闭环通过后增加版本化分支/并行/汇合、多席位完成条件及 trigger 契约的实现；先明确剩余分支取消、重复触发和恢复规则，再启用相应能力。 |

## 依赖与协作

- M1 契约预留依赖 T00，并与 T06 同步对象边界。
- M2 运行逻辑依赖 T01 会话授权、T02 已提交版本、T03 审定/发布/资源状态接口、T04 outbox 与消费去重；可先以契约桩开发，再完成真实接线。
- T06 在授权会话上下文调用 T05 领取/交付接口，不能自行更新有效租约；T07 暴露相关 REST/CLI；T08 提供重启、恢复代次和故障注入环境。

## 可测验收

| 场景 | 通过条件 |
|---|---|
| 两个会话同时抢一个席位 | 仅一个取得有效 Attempt；另一方收到稳定冲突码。 |
| 同一会话过期后重领 | 旧 Attempt 的心跳、提交和候选写入均被拒；新轮次可继续，旧记录保留。 |
| 外部执行失联或取消未确认 | 旧 fence 失效；任务不会立即派出可能重复执行的第二份。 |
| 服务重启与事件重复/乱序 | Flow/StepRun 从持久状态恢复；同一个业务事件不创建重复任务、检查或发布命令。 |
| 签出与资源锁竞态 | exclusive 拒绝未授权并发写；advisory 仍检查基线；锁定和撤权在最终接受边界生效。 |
| 完整闭环与返工 | 至少退回一次；旧待审目标不可再批准；新版 approved 未发布时下游仍取旧发布版本；发布成功后再解锁依赖。 |

## 范围外

M1 不启用业务流程门禁；M2 不实现任意工作流语言、模型生成外层执行图或多席位通用调度。T05 不调用模型、不托管 Agent 进程、不修改台账事实、不安装外部编排平台，也不在任务卡确认时创建 cron 或事件自动化。
