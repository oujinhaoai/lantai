# T02 资源与存储

状态：**待确认 / 未开始**。按子任务标注阶段验收，M1 完成不代表整卡完成。共同规则与依赖见[任务总表](README.md)。

## 目标

提供稳定的资源身份、可重用名称与不可变版本内容；可靠接收和交付大文件，保证去重不会绕过授权，未提交内容不会出现在正常读取入口。

## 拥有模块与数据

| 模块 | 拥有的数据与边界 |
|---|---|
| `catalog` | 项目/资产说明修订、类型 schema、规范化 manifest、别名历史文件及引用解析逻辑；占名和当前生效的提交控制通过 T03 台账接口完成 |
| `storage` | Blob、暂存、版本安装、文件读写和校验适配器；不自行宣布资源审定或业务提交完成 |
| 上传/传输 | `runtime.db` 中本模块拥有的 UploadSession、分片状态、BlobGrant、ReadGrant；提供流式传输与调度接口 |

T03 是版本业务提交和生命周期接受的唯一负责人；T02 返回可验证的安装结果与内容证明，不直接写 T03 的控制表。T02 管字节操作，T03 管这些操作的业务意图、授权前提和持久结果。

| T02.2 | M1 | 实现内容寻址、流式 SHA-256、上传会话、分片重试和中断续传；区分上传到期与提交 pin；相同字节去重，未校验或不完整字节不得成为可引用内容 |
| T02.3 | M1 | 实现 BlobGrant/ReadGrant：复用绑定主体、项目、操作和来源；下载绑定版本/文件及本人会话，每个新 GET/Range 实时核验；无授权哈希查询不泄露已有内容，已撤销授权不等签名自然过期 |
| T02.4 | M1 | 实现幂等的文件安装、说明修订和证据追加适配器；输出 manifest 摘要与完整性证明，配合 T03 的 prepared/installed/committed 协议；跨平台验证刷盘、文件占用、空间不足、硬链接回退和路径冲突 |

## 依赖与并行方式

- 开始前：T00 提供文件安装、版本提交、命名空间、引用/限制查询、pin 与错误契约及桩。
- T02 与 T03 并行：T02 实现内容与安装端，T03 实现提交控制端；M1 联合证明一个 operation 只产生一个完整版本，无整卡级相互前置关系。
- 正式集成先通过 T08.1 的实例启动/五库迁移/维护屏障门禁；合成内存/临时目录桩不替代该门禁。
- 授权接入 T01；内容用途和有效来源限制经 T03 接口取得；精确读取无需等待 T04 索引追平。
- T07 负责接口/传输监听、路由、超时和客户端连接池；T08 负责网关配置、仅本机运维面、容量/吞吐测量与恢复。T02 返回可用传输地址所需描述，不要求客户端拼接内部监听地址。

## 验收

- M1：合成 1 GB 文件中断后可续传，所有文件哈希一致；内存占用不随总文件大小线性增长；异内容分片重试拒绝。
- 名称释放后同名新资产不会接管旧永久引用；当前浮动导航可用，含糊的旧路径版本引用明确报错。
- 仅持受限内容哈希、转发下载地址或别人的 grant 均无法取件；已撤权后的新 Range 请求拒绝，已发送的字节不声称可以回收。
- 任一安装/台账间隙退出，未提交文件均不可正常下载；恢复结果为完整提交、可继续操作或有原因的隔离，不返回半份成功。
- 三个批量会话并行上传/拉取时，交互传输保有容量；接口 p95 暂按空载的两倍内作为验证起点，记录环境与结果后固化阈值。增加第二个外部端口不作为自动优化动作。
- M2：回收一个版本不删除其他版本仍引用的 Blob；GC 与新提交、恢复、备份复制并发时不损坏存活内容；损坏/未重建索引不能授权物理回收。
- M2：新上下文未审定时不改变已有生效版本；任务记录其实际读取的上下文与决议版本，旧决议被替代后仍可追溯。
