# T06 — Agent 执行与节点

用途：**公开任务基线**。按子任务标注阶段验收，M1 完成不代表整卡完成。进度管理、共同规则与依赖见[任务总表](README.md)。

## 目标

为任务提供可替换执行后端，同时保留“需要判断的 Task”和“确定性处理的 Job”两条执行路径。M1 预留协议；M2 用 manual-cli 登记已有手动会话，并提供最小 worker/检查闭环；M3 才增加 Runner 自动托管和可选 DeerFlow 等后端。扩展的登记、启用与宿主归 [T09](T09-extension-platform.md)，T06 通过其协议调用处理器，保留业务派发和结果验收职责。

## 模块与数据归属

| 模块 | 唯一拥有的数据与职责 | 权限边界 |
|---|---|---|
| `agent_execution` | `runtime.db` 中 TaskRun、AgentStepRun、ExecutionProfile 固定版本引用/运行快照、adapter 映射、预算记录、HumanInputRequest、工具回执；checkpoint 与候选证据按受控存储协议保留 | 引用 T05 Attempt/lease；不得自己生成有效任务 fence 或修改审定/发布 |
| `jobs` | `runtime.db` 中 Job、JobAttempt、作业租约、派发与重试状态、处理器/输入指纹 | 作业租约与 T05 任务租约是不同类型；结果由服务端验收 |
| `node` | 节点在线状态、能力观测、资源占用/租约 | 身份与授权归 T01；自报能力不直接授予权限；扩展实例健康与激活代次归 T09 |
| adapter / worker / runner | 通过公开协议读取任务或作业、记录执行映射、提交受限产物和观察 | 不共享五库，不直接写规范目录；Runner 请求服务端签发收窄会话，不持有签名密钥 |

checkpoint 保存固定输入、结构化执行摘要、已接受产物、工具回执水位及后端恢复指针；不要求模型隐藏思维链。临时工作区不是资产真源，最终产物通过 T02/T03 的普通提交协议进入兰台。

## 具体子任务

| 编号 | 阶段 | 工作与交付 |
|---|---|---|
| T06.1 | M1 协议预留 | 向 T00 提交 ExecutionProfile、TaskRun、AgentStepRun、Checkpoint、ArtifactCandidate、ToolOperation、JobAttempt 与能力声明 schema；定义 CLI/HTTP `describe/start/lookup/status/resume/cancel/result`、稳定启动键、结果摘要和假后端样例。与 T09.1 对齐产物/证据的插件 ID、版本及包摘要；扩展 activation 联合检查随 M2 宿主接入，任务 fence 与扩展代次保持不同类型。只预留契约，不启动 Agent 服务。 |
| T06.2 | M2 | 实现 manual-cli：登记人工已启动的合法会话与 T05 当前 Attempt，记录进展、候选和封存结果。重复 start 登记返回同一 execution_id，不启动第二个进程；无需额外 daemon，不声明无法强制的进程终止或精确费用限制。 |
| T06.3 | M2 | 实现节点能力登记、最小作业队列/worker，与 T09.4 按文件协议 spawn/run/exit 接入一个一次性合成素材结构检查插件；输入输出按 schema、manifest 摘要、插件 ID/版本/包摘要及激活代次校验。能力来自静态清单与获授权的受限 probe，不要求常驻控制握手。T06 拥有派发、作业超时、分类重试与结果去重，T09 提供宿主限额及进程回收能力。内部 worker 也使用相同应用接口，不能直接改业务表。 |
| T06.4 | M2 | 实现人工输入、checkpoint/交接、预算累计、工具范围和恢复对账。副作用先记 intent；结果不明且不可幂等/查询时阻塞恢复。取消先撤销后续写入权，再等待实际停止确认；旧 epoch/fence 结果拒绝。 |
| T06.5 | M2 | 提供业务执行协议测试与故障后端：接受 start 后丢响应、同键异摘要、终态结果延迟、取消不支持、重复/乱序观察、恢复格式不兼容。与 T09.10 共享 fixture，分别核验任务/作业接受规则与扩展宿主生命周期。结果只成为候选或检查证据，不能因后端 success 直接通过审定或发布。 |
| T06.6 | M3 后续 | 实现经授权的 Runner 托管、预算强制能力验证和一个可选自动后端；DeerFlow 需锁版本并通过同一协议测试。event/cron trigger 与 T05 协作设计持久去重、并发/漏跑策略，只有单独启用后才调度；本卡不默认开启。 |
| T06.7 | 历史索引，无实现任务 | 原插件治理条件任务已整体转交 [T09 扩展平台](T09-extension-platform.md)：登记配置、宿主、包治理、CLI/网页贡献、服务连接器及故障套件统一在该卡跟踪。本编号仅供旧引用定位，不再独立实施、计数或验收。 |

## 依赖与协作

- M1 与 T00、T05、T09.1 并行定义契约；不依赖安装外部 Agent 平台或动态插件 loader。
- M2 依赖 T01 会话/节点/worker 授权、T05 任务租约、T02 上传与候选文件、T03 检查/验收事实、T04 持久命令和事件。
- T09.4/T09.5 提供一次性进程宿主、有效启用策略及固定包版本；T06 提供作业/任务协议与合成处理器使用场景。双方先用桩并行，M2 联合集成门禁要求真实文件协议宿主及业务接受规则同时通过，不形成整卡依赖循环，也不要求常驻控制协议。
- T07 承接 HTTP/CLI 暴露与错误映射；T09 管理扩展进程生命周期，T08 提供平台资源限制配置、核心启动及恢复演练。M3 自动化以 M2 全闭环及真实后端重跑协议测试为前提。
- 插件实现规格以[扩展设计](../extensions.md)为唯一权威：T09 在 M1 保存内置登记，M2 扩充 main 启用配置和 runtime 激活/宿主故障状态，并引用 T06 的 invocation/attempt；T01 提供授权，包人审引用 T03 台账。T06 固定执行所用包/配置/输入版本，升级后的适用性判定不改写旧检查证据或历史人审。

## 可测验收

| 场景 | 通过条件 |
|---|---|
| 重复 start 与响应丢失 | manual-cli 只登记一次；假后端只启动一次；同键异摘要明确冲突。无法证明是否已启动时进入 needs_reconciliation。 |
| 模糊外部副作用 | 不自动换键重试；已完成回执可补录，确认未执行后才可重试。 |
| 取消与人工等待 | manual-cli 不伪报已停止；未确认保持 cancelling/needs_reconciliation；答复不复活旧 Attempt，也不能转为资产人审凭据。 |
| 后端结果与恢复 | result 固定到指定 run 和结果摘要；checkpoint 不兼容给出声明的恢复路径；重试用量累计且旧 epoch/fence 被拒。 |
| 最小 worker/插件 | 合成正常文件产生绑定输入摘要的报告，损坏文件产生可解释失败；超时可回收资源；非法路径、越界输出和错误 schema 被拒。 |
| 权限与能力不足 | worker、Runner、adapter 无审定/发布权限；能力声明未满足任务时拒绝派发；对外部动作无法实施约束的后端不能启用无人值守。 |
| 执行与扩展平台集成 | 派发引用 T09 有效启用策略与固定 ActivationSnapshot；任务 fence 和插件激活代次均核验；输出绑定处理器版本。合法检查 fail 保留业务证据，不计为宿主崩溃；包治理与熔断本身由 T09 验收。 |

## 范围外

包登记/启用/配置、插件宿主、升级/熔断、插件 SDK 和 CLI/网页贡献平台归 T09，本卡不再另建治理模块。M2 不要求 DeerFlow、LangGraph、通用 planner、常驻 adapter 或自动拉起会话；不建设任意 shell 执行平台，不承诺取消等于撤销第三方动作。复杂 GPU 调度、媒体全格式插件、全局记忆和自动多 Agent 计划留后续；M3 内容是任务卡后续阶段，不随本次文档交付启用。
