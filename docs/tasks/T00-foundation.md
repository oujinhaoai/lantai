# T00 · 工程与共享契约

用途：**公开任务基线**。阶段：M1 起步；包含 M2/M3 所需的最小协议预留。进度管理与共同规则见[任务总表](README.md)。

目标：让各模块能够按同一套身份、ID、错误、操作、事件和文件协议并行实现，先验证会影响整体结构的技术假设。

## 拥有的范围

`api/`、`schemas/` 的共同规则，工程组装方式、构建/生成脚本、测试基础与公开 ADR。领域规则仍由所属任务定义；不建立全局业务回执库。

## 依赖与交接

无代码前置；维护者确认本版目录与任务后开始。先交付 T00.1/T00.2 的最小接口，T08.1 和 T07.1 可随之推进；技术验证结论由受影响模块共同确认再锁版。

T09 拥有扩展契约与登记规则，T00 提供公共版本、生成与测试基础，不代管扩展状态。T09.1–T09.3 的 M1 范围仅为清单、扩展点 ID、内置静态登记和来源字段；M2 才接一次性进程宿主，依赖图/服务容器按需建设。T00 不等待所有未来 schema 全部完成才交接 M1。插件实现规格以[扩展设计](../extensions.md)为唯一权威，阶段范围见 [T09](T09-extension-platform.md)。

## 验收

- 正常与非法样例得到明确结果；同一错误在契约及示例中含义一致。
- API 生成可重复、重生成无差异；未知字段/可空/扩展字段行为明确，生成通过不替代请求验证。
- T02/T03 能用桩分别编译验证，彼此没有整卡依赖循环；每张表、文件和事件有明确所有者。
- 三平台技术验证和依赖版本有结果表；不支持的行为明确拒绝或记录待完成，不能写成已支持。
- M1 的 T06 协议有同 operation 重试与过期任务 fence 反例；T09 有清单错误、重复 ID、缺失来源字段和不支持能力的拒绝样例。M2 的宿主/activation/隔离验收不提前算作通过，也不要求 M1 建跨插件依赖图。
- 合成数据及示例无私有环境信息，凭据不进入日志和仓库。

## 范围外

真实素材扫描/迁移、生产部署、完整网页、通用流程语言、DeerFlow 安装、定时触发和多进程写入。M1 不建动态插件 loader、通用 DI、跨插件依赖图、多层配置或卸载容器，不下载或执行第三方扩展；静态契约验收不代替后续宿主及按需网页隔离验收。
