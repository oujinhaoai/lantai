# T00 · 工程与共享契约

状态：**待确认 / 未开始**。阶段：M1 起步；包含 M2/M3 所需的最小协议预留。

目标：让各模块能够按同一套身份、ID、错误、操作、事件和文件协议并行实现，先验证会影响整体结构的技术假设。

## 拥有的范围

`api/`、`schemas/` 的共同规则，工程组装方式、构建/生成脚本、测试基础与公开 ADR。领域规则仍由所属任务定义；不建立全局业务回执库。

## 依赖与交接

无代码前置；维护者确认本版目录与任务后开始。先交付 T00.1/T00.2 的最小接口，T08.1 和 T07.1 可随之推进；技术验证结论由受影响模块共同确认再锁版。

T09 拥有扩展领域契约与登记/生命周期规则，T00 提供公共协议、生成与隔离验证基础，不代管扩展状态。T09.1–T09.3 的 M1 范围为契约、登记配置与官方静态注册；M2 才接进程宿主。T00 不等待所有未来 schema 全部完成才交接 M1，后续新增协议随相应阶段验证。详见[扩展设计](../extensions.md)与 [T09](T09-extension-platform.md)。

## 验收

- 正常与非法样例得到明确结果；同一错误在契约及示例中含义一致。
- API 生成可重复、重生成无差异；未知字段/可空/扩展字段行为明确，生成通过不替代请求验证。
- T02/T03 能用桩分别编译验证，彼此没有整卡依赖循环；每张表、文件和事件有明确所有者。
- 三平台技术验证和依赖版本有结果表；不支持的行为明确拒绝或记录待完成，不能写成已支持。
- T06/T09 协议有同 operation 重试、旧 activation/任务 fence、缺依赖、能力不足及畸形消息反例；隔离小样记录实际宿主能力，未验证的隔离不能成为外部代码自动启用条件。
- 合成数据及示例无私有环境信息，凭据不进入日志和仓库。

## 范围外

真实素材扫描/迁移、生产部署、完整网页、通用流程语言、DeerFlow 安装、定时触发和多进程写入。M1 不建动态插件 loader、不下载或执行第三方扩展，也不以协议/隔离小样代替 T09 的后续生产宿主与网页隔离验收。
