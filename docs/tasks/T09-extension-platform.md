# T09 · 三端扩展平台

用途：**公开任务基线**。本卡承接原 T06.7，插件实现规格以[服务端、客户端与网页扩展设计 v2.1](../extensions.md)为唯一权威，进度管理与共同规则见[任务总表](README.md)；不因接口预留而提前安装或执行第三方代码。

## 目标与归属

服务端、节点、CLI 和网页共用包清单与身份，按阶段启用能力。M1 只有服务端/节点 processor、validator 的内置静态登记；M2 运行一次性处理器并接包治理与显式 CLI；M3 提供官方/声明式 UI。跨插件依赖、常驻服务容器和第三方网页按实际需求另行实施。

| 所有者 | 唯一职责 |
|---|---|
| T09 `extensions` | M1 的包清单与内置静态登记；M2 的 main 启用配置、runtime 激活/宿主故障状态及一次性宿主，按引用关联 T06 invocation/attempt；常驻实例和服务容器按需增加，不在 M1 预建 |
| T02/T03 | 包文件和 manifest、不可变版本、包审定及检查证据；T09 只引用其权威事实 |
| T01 | 身份、短期服务能力、当前权限及绑定动作的人类授权；插件不能生成授权 |
| T05/T06 | Task/Attempt/fence、TaskRun/AgentStepRun、Job/JobAttempt 和业务重试；T09 不再建一套任务状态机 |
| T07/T08 | HTTP/CLI/MCP/SDK 接线；网关、进程资源约束、密钥设施、恢复与部署验证 |

网页 registry/broker 位于 web，服务端宿主位于 internal，扩展源码/清单位于 plugins，协议位于 schemas，插件 SDK 位于 sdk。保持现有 11 个一级目录。

## 子任务

| ID | 阶段 | 工作与交付 |
|---|---|---|
| T09.1 | M1 | 定单一 `extension.yaml` / `lantai.extension/v1` 清单，processor 字段合入；定义扩展点 ID、插件 ID/版本/包摘要及产物/证据引用。仅服务端/节点 `artifact.processor`、`asset.validator` 内置实现可登记，CLI/Web 字段仅预留；不支持能力及非空插件依赖声明明确拒绝。T00 维护公共版本规则，不另设 plugin.yaml/module.yaml。 |
| T09.2 | M1 内置登记；M2 启用配置 | M1 登记随本馆发布的内置包身份与不可变摘要，并使产物/证据可追溯；只开放本阶段支持的能力，不预建外部包启用工作流、多层配置、健康部署模型或客户端激活状态。M2 再与 T09.5 联合实现有效启用范围、冻结配置与配置 revision，引用当前审定及授权，不另建审批真源。 |
| T09.3 | M1 简单登记；依赖生命周期按需 | 实现显式静态注册和重复 ID/不支持扩展点拒绝，不引入通用 DI、跨插件依赖图或卸载容器。后续出现真实 provider/consumer 需求时另拆依赖解析与生命周期执行卡，保留本 ID 追溯；不能把后续部分计入 M1 门禁。 |
| T09.4 | M2 | 实现一次性进程宿主：按文件协议 spawn/run/exit，限制输入输出、环境、工作目录、时间与资源并回收进程树；不强制 Describe/Negotiate/Configure/Health/Drain/Stop。只有静态清单无法确认的能力才做启用前 capability probe，先获授权并在受限环境运行；T06 接通一个真实检查器。T08 提供三平台实测能力矩阵，不满足要求时拒绝或明确只许受信任部署。 |
| T09.5 | M2 | 包导入只静态校验；包审定、必要的受限 probe、目标/范围启用各守授权边界，probe 成功不自动启用。实现不可变摘要、激活代次、撤权、停止接单/等待或终止在途进程的排空、熔断、升级与回滚预检；引用 T06 未决调用协调回收/对账，拒收失效结果。按规格 §11.2 默认执行 10 分钟滚动窗内 5 次运行故障即 open、15 分钟冷却后半开只允许 1 个探针，探针运行正常则重置、运行故障再次 open；合法检查 fail 等业务结果不计故障。历史检查证据不改写，按 Profile 判断适用性。 |
| T09.6 | M2 | 与 T07 接通显式 `lantai ext run`、本地安装注册和受控 MCP 投影；路径/摘要核验、不遮蔽内置命令、不自动搜索 PATH/CWD；argv/env/cwd 受控，不传长期用户凭据或人审能力。 |
| T09.7 | M3 | 官方组件与声明式网页贡献、设置表单、预览/侧栏/动作/结果插槽；稳定选择与后备展示，按视图清理订阅。核心登录/授权/审定页面仍由宿主维护。 |
| T09.8 | 按需，不属 M3 承诺 | 出现第三方网页需求后，单独验证独立 origin、与主站不同的可注册域及目标浏览器 site 隔离、sandbox/CSP 和有界 broker；内网特殊后缀须实测，不能仅凭子域名认定跨站。来源无会话凭据，精确 Origin/CSRF、消息、导航、撤权和插件间隔离全部通过才允许第三方 iframe。部署条件不足继续只用官方/声明式 UI。 |
| T09.9 | 按实际需求 | 常驻 service、连接器或事件消费分别有真实需求才实现；只有实际常驻实例需要 Describe/Negotiate/Configure/Health/Drain/Stop，有跨插件服务需求才加依赖生命周期。命名空间路由和方法/schema 固定，核心统一授权/限额；外部效果可幂等或查询/对账，不扩成任意代理或同步事务钩子。 |
| T09.10 | 各阶段及按需能力 | 维护 fixture 与兼容矩阵；M1 验证清单/扩展点/静态登记/来源字段及不支持能力拒绝；M2 验证文件协议一次性进程、受限 probe、CLI、撤权、排空与熔断；M3 验证官方/声明式 UI。第三方网页、跨插件依赖及常驻协议随对应按需任务另加测试，不作为 M1–M3 的隐含前置。 |

## 依赖与推进

M1 与 T00/T02/T03 对齐统一清单和产物/证据来源，使用内置静态登记验证；不等待 M2 包人审，也不建通用插件框架。M2 与 T01/T03/T06 联合完成“静态导入→包审定→必要时获授权受限 probe→显式启用→一次性执行→停用”的纵向闭环。T06 的 manual-cli 可先按已固定协议完成，不依赖所有扩展能力。

T09.7 随 M3 网页工程推进，并由 T07 接通公开 API。T09.3 的依赖生命周期后续部分、T09.8 第三方网页、T09.9 常驻服务各有真实需求才另写执行卡；不属于 M3 必交范围。T09.10 随已选定的能力验收，不提前实现后续宿主。

## 验收

| 场景 | 通过条件 |
|---|---|
| M1 清单与注册 | 只有一份包清单；CLI/Web 或其他不支持能力不激活；重复 ID/未知扩展点明确拒绝；产物/证据固定插件 ID、版本和包摘要，不要求通用依赖图 |
| M2 登记与恢复 | 同 ID/version 不可换摘要；启用响应丢失不重复执行；五库所有者明确，无第二审批真源 |
| 按需依赖生命周期 | 真实依赖需求立项后验证缺依赖/环/冲突及清理；不列入 M1 静态登记门禁 |
| 权限 | 安装不等于启用；服务器启用不等于本机/网页授权；撤权或过期 generation/fence 在最终接受时拒绝 |
| 一次性宿主与 probe | 文件协议可完成 spawn/run/exit；probe 未授权不执行，探测结果不等于获权；超时/撤权后回收进程并拒收迟到结果，不要求常驻握手 |
| 运行故障 | 超时、畸形结果、崩溃不能变成 pass；用可控时钟验证 10 分钟/5 次、15 分钟冷却、唯一半开探针和成功重置/失败再次 open；合法检查 fail 不误熔断；平台无法强制的限制如实报告 |
| 升级排空 | 新调用绑定新版本；旧调用仅在仍有效的在途授权下收尾；安全撤销立即拒收；状态不兼容明确阻止回滚 |
| 外部效果 | 响应丢失后按同 operation 查询/对账；无幂等或查询能力时不自动重发 |
| CLI | PATH/CWD 同名文件不执行；已登记入口被替换时拒绝；插件无法覆盖 auth/review/purge 等核心命令 |
| M3 官方/声明式 Web | 插槽/设置按契约工作，视图失败有后备，订阅可清理；登录和人审仍由宿主控制 |
| 按需第三方 Web | 独立 origin 与 site 隔离、无会话凭据的部署条件已证实；伪造 origin/source/nonce、CSRF、越界对象、旧页面和注销后消息被拒，不泄露凭据或产生 HumanGrant |

## 范围外

公开市场、自动更新、未经人审授权执行外部包、任意 Go 动态共享库、WebAssembly 宿主、同源第三方 React federation，以及用 SDK/DI/子进程冒充安全沙箱。候选协议与框架在小样通过前不锁定为依赖。
