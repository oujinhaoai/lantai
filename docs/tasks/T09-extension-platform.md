# T09 · 三端扩展平台

状态：**设计已拆分，待确认 / 未开始**。本卡承接原 T06.7，实施范围以[扩展设计 v2](../extensions.md)为准；不因接口预留而提前安装或执行第三方代码。

## 目标与归属

服务端、节点、CLI 和网页共用扩展身份与兼容规则，各宿主独立授权与执行。优先支持声明式扩展和官方静态模块，再验证进程外处理器与隔离网页。插件市场、通用动态 loader 和任意核心替换不作为首期目标。

| 所有者 | 唯一职责 |
|---|---|
| T09 `extensions` | main：登记、启用范围、配置 revision；runtime：实例、激活快照、部署进度、健康、熔断；宿主 registry、manager、broker、可撤销注册 |
| T02/T03 | 包文件和 manifest、不可变版本、包审定及检查证据；T09 只引用其权威事实 |
| T01 | 身份、短期服务能力、当前权限及绑定动作的人类授权；插件不能生成授权 |
| T05/T06 | Task/Attempt/fence、TaskRun/AgentStepRun、Job/JobAttempt 和业务重试；T09 不再建一套任务状态机 |
| T07/T08 | HTTP/CLI/MCP/SDK 接线；网关、进程资源约束、密钥设施、恢复与部署验证 |

网页 registry/broker 位于 web，服务端宿主位于 internal，扩展源码/清单位于 plugins，协议位于 schemas，插件 SDK 位于 sdk。保持现有 11 个一级目录。

## 依赖与推进

M1 与 T00/T01/T02/T03 定包与授权契约，使用官方静态包验证，不等待 M2 的完整包人审。M2 在 T03 人审能力和 T06 最小 worker 成立后，完成“导入→审定→启用→执行→停用”的纵向闭环。T06 的 manual-cli 可先按已固定协议完成，不依赖所有动态扩展能力。

T09.7 随独立网页工程推进，并由 T07 接通公开 API；T09.8 是第三方代码的额外出口，不阻塞首方网页。T09.9 每项能力另写具体执行卡，预留扩展点不等于同时建设全部服务。T09.10 按阶段完成，不要求 M1 提前跑 M3 的完整浏览器套件。

## 验收

| 场景 | 通过条件 |
|---|---|
| 登记与恢复 | 同 ID/version 不可换摘要；启用响应丢失不重复执行；五库所有者明确，无第二审批真源 |
| 注册与依赖 | 缺必需服务/依赖环/冲突可诊断；卸载/失败后无残留路由、命令、订阅或后台任务 |
| 权限 | 安装不等于启用；服务器启用不等于本机/网页授权；撤权或过期 generation/fence 在最终接受时拒绝 |
| 运行故障 | 超时、畸形响应、崩溃不能变成 pass；合法检查 fail 不误熔断；平台无法强制的限制如实报告 |
| 升级排空 | 新调用绑定新版本；旧调用仅在仍有效的在途授权下收尾；安全撤销立即拒收；状态不兼容明确阻止回滚 |
| 外部效果 | 响应丢失后按同 operation 查询/对账；无幂等或查询能力时不自动重发 |
| CLI | PATH/CWD 同名文件不执行；已登记入口被替换时拒绝；插件无法覆盖 auth/review/purge 等核心命令 |
| Web | 伪造 origin/source/nonce、越界对象、旧页面和注销后消息拒绝；不泄露主站凭据；插件不能产生 HumanGrant；视图失败有后备 |

## 范围外

公开市场、自动更新、未经人审的包安装执行、任意 Go 动态共享库、WebAssembly 宿主、同源第三方 React federation，以及用 SDK/DI/子进程冒充安全沙箱。候选协议与框架在小样通过前不锁定为依赖。
