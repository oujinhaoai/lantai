# T08 · 运维、恢复与部署

状态：**待确认 / 未开始**。阶段：M1 起步，M2/M3 扩充。

目标：从第一次提交起就具备一致的启动、维护、诊断与恢复机制，而不是功能完成后再补运维。

## 拥有的范围

`operations`、实例生命周期、平台适配与迁移编排，`deploy/` 模板，以及阶段恢复/平台验收。业务表 migration 由所属模块编写，T08 管顺序和兼容性；GC 候选资格由业务模块裁决，T08 执行可恢复作业。

## 依赖与交接

- T08.1 只依赖 T00 的工程和存储契约，是 T01/T02/T03/T04 生产集成的基础；与 T07.1 的 transport 骨架并行。
- T08.2/T08.3 依赖 T02/T03 的 operation/文件边界及 T04 的事件水位，不能只备份各库而忽略共同恢复点。
- T08.4 与 T07 分工：T07 实现监听/HTTP 行为，T08 提供安全的配置、部署和验收。
- T08.5 在每个阶段持续集成；T08.6 的业务规则归 T03，物理执行服从 T02 文件和 pin 协议。

## 验收

扩展宿主与 [T09](T09-extension-platform.md) 联合验证：T08 提供实际 OS 隔离能力、密钥引用、进程树回收、健康汇总及包/状态备份；M3 网页扩展另测独立 origin 路由与浏览器策略。扩展贡献不自行绑定公网端口，停用外部共享服务默认仅撤销兰台连接与授权。

- 双实例写同一数据根被拒；未完成迁移/恢复时 readiness 拒绝开放业务；维护屏障覆盖后台写入。
- 每个提交和清除持久化边界崩溃后，可恢复或明确隔离，不能重复登记或无证据清理。
- complete 备份恢复到空目录后，内容哈希及权限/审定/发布/墓碑一致；旧 fence 和凭据按恢复规则失效。
- 三个 Agent 并发批量传输时测 API p95；以空载的 2 倍为待实测起点，阈值在 T00 报告中确认；交互传输有保留额度且批量不永久饥饿。
- 从非本机网络不能访问指标/pprof；部署模板不包含真实地址、凭据或数据目录。
- 平台支持、长期运行与恢复耗时都附实测记录。初始演练目标：本机 RPO ≤24 小时、整机损失 RPO ≤7 天、试点 RTO ≤4 小时；未执行备份计划时不宣称满足目标。

## 范围外

本任务卡不授权直接修改生产主机。开发确认后先在本地与隔离测试环境验收；真实部署与数据迁移另按具体执行计划推进。M7 长连接、M8 馆际/存储节点不作为首轮依赖。
