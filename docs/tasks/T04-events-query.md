# T04 事件与查询

状态：**待确认 / 未开始**。按子任务标注阶段验收，M1 完成不代表整卡完成。共同规则与依赖见[任务总表](README.md)。

## 目标

可靠传播业务变化，提供可重建、受权限限制的查询；明确事件至少一次交付、业务幂等消费、游标过期和权限变化后的同步行为，不让投影取代权威事实。

## 拥有模块与数据

| 模块 | 拥有的数据与边界 |
|---|---|
| `events` | `events.db` 的 event_id 去重、收录顺序、保留/审计水位，审计导出文件及状态 |
| `query` / 投影 | `index.db` 的目录/检索/关联投影、构建代次和消费水位；本模块的消费者去重记录 |
| 收件箱读取 | M2 在 `runtime.db` 中由 query 拥有的已读位置；任务归属/状态仍从 T05、审定目标从 T03 取得 |

源业务模块拥有自己的 outbox 和事务；T04 经 T00 的 outbox 适配接口拉取及确认，不任意 SQL 修改其他模块的业务表。业务消费者的去重记录与目标状态由该消费者所属模块在本库事务提交。

## 依赖与并行方式

- 开始前：T00 提供事件信封、source outbox、消费者事务适配、分页与游标契约；可用合成事件并行实现 relay 和查询骨架。
- M1：接 T01 当前读取权限，T02 文件枚举与 T03 权威状态；与 T08 联合验收停机恢复、备份水位和重建。生产事件不需要等查询服务 ready 才能提交。
- 正式集成以 T08.1 的实例启动/五库迁移/维护屏障为前置；relay 与合成消费者仍可在接口桩上并行实施。
- M2：T05 提供任务可见范围/指派变化，T03 提供审定/发布事实；T07 提供查询路由和客户端重同步行为。
- 接口查询/长轮询使用接口面；M7 的 SSE/节点长连接面后置。指标仅交给 T08 的本机运维面，不能挂到公网关路径。

## 验收

- 源 outbox 在事件已收录但未确认时重启，只产生一个逻辑事件；消费者事务前后退出都不会出现“状态未写但游标已前进”。
- 乱序事件按对象 revision 对账；跨库时间先后不能仅靠全局收录序号推断；不可处理事件有稳定故障状态，不无限快速重试。
- 删除 index 后重建结果与权威文件/台账一致；查询过滤当前权限，即使索引落后也不暴露受限对象或来源详情。
- 事件全部被权限过滤时游标仍可前移；游标超窗有明确错误；重同步先固定起点再扫描/重放，已删除或已撤权的客户端条目被移除。
- 审计末行被截断可恢复，重复物理记录按 event_id 识别；尚未安全导出或关键消费者需要的历史不会被时间窗口直接清掉。
- M2：同一任务事件多次投递不会重复生成收件箱事项；已读位置不修改任务结果；撤权和改派后旧收件箱无法继续读取对象详情。
