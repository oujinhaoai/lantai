# 真人批准后接棒：设计评估，尚未实施

本设计只评估角色分工和候选协议。当前 `internal/identity/actions.go` 的 HumanOnly、
原 session-bound HumanGrant、设备独立 human CLI 和原生续做人类见证继续生效。
本文不注册新路由、schema、凭据、授权或设备，不改变任一服务端接受条件。

## 分项边界与建议

| 场景 | 当前边界 | 本轮建议 | 可进一步评估的最小接棒动作 |
| --- | --- | --- | --- |
| 备份状态/历史/取消 | 真人管理员；维护身份只绑定当前 job/attempt | 保持现状，先补正式本人 CLI | 仅对准确获批 job 返回脱敏状态；取消须绑定原 attempt 并等待真实退出 |
| 备份开始/续传/计划 | 本人管理员新鲜精确批准 | 保持 HumanOnly | 可评估一次指定动作执行；不包含后续任务、不同捕获点或自动计划扩张 |
| 完整恢复包导出 | 本人及精确包摘要批准；包含恢复能力 | 继续禁止 Agent 接棒 | 本设计不建议向 Agent 发包或下载许可 |
| 恢复安装认领/新管理员因素/接受恢复点 | 受保护新目标与本人因素 | 继续禁止 Agent 接棒 | 本人完成后 Agent 在自身获准项目内验证所选固定版本字节 |
| 设备认领/配对/工作区批准 | 同本人双会话、单项目、最长15分钟独立 CLI | 保持现状 | 若另行允许，只委派准确预检摘要的一个 job，不继承设备会话 |
| 设备 poll/heartbeat/result/取消 | 准确设备 session + T06 唯一 attempt/fence | 保持现状 | 沿原 Job/Attempt 接受；禁止增加第二执行队列或清除 unknown |
| 人类业务终审/rights 放宽/清除/Hold | 既有本人权限和精确证明 | 继续禁止 Agent 接棒 | Agent 仅准备准确目标及读取自身可见的接受结果 |
| 原生软件续做人类见证 | 新鲜本人因素、核心复验的独立语义 | 继续禁止 Agent 接棒 | 机器 DCC 运行证明另立需求，不从上传 JSON 推导 |

选择保留现状的代价是若干高权限操作仍需本人客户端，但不会引入新的恢复能力受领者。
新增接棒可降低操作中途的人工占用，却需新增明确授权语义、撤销路径和接受测试。
建议先完成无权限扩张的普通操作工具；只有维护者选定具体动作后再立实现卡。

## 候选协议的必备绑定

以下为后续设计约束，不是可调用 API 或现有 HumanGrant 的新解释。

T01 拥有接棒授权记录与审计；T08 仍拥有备份一致性/捕获点，T06 仍拥有 JobAttempt、
lease/fence 和副作用对账。通过领域接口传递固定事实，不跨库联表或共用事务。
不能将“真人已批准”布尔值、旧 grant ID、浏览器 Cookie 或设备 token 当作接棒令牌。

若采用新协议，批准对象至少绑定：提出人的 principal/session；明确受领 Agent
principal/session 和 audience；准确 action；单项目（如适用）；实例与 recovery epoch；
目标 job/attempt 或资产/版本/manifest digest；预期 revision；冻结请求摘要；工作区
绑定摘要（设备场景）；开始/到期时间；一次性授权 ID；原 operation/correlation。
TTL 不得跨越任一参与会话、设备、租约或批准期限，默认不自动续期，不形成持久凭据。
Action 不能使用通配符；批准后不得换收件人、项目、文件、用途、参数或目标。

受领者仍用自己的现有会话认证，现场权限和被授权的最小动作同时满足才能执行。
批准本身不扩大其角色/scope，不允许 recipient 再委托。批准与执行者分别审计，
记录原 request digest、grant/intent ID、operation、attempt/fence 和最终接受结果。
消费与幂等回执由原所有者原子处理，重放返回同一 operation，绝不形成第二副作用。

## 状态、撤销与未知副作用

候选意图阶段：proposed → awaiting_human → approved → executing → terminal；
expired/revoked/needs_reconciliation 为显式分支，不能把执行成功等同业务审定。
这只描述意图记录，业务执行状态仍在原 operation、backup 或 Job/Attempt。

- 批准前：受领者仅能发现自己提出的脱敏请求和缺失因素，不能枚举他人任务或读取全包信息。
- 批准后：领取前与最终接受时复验双方身份/会话、权限、摘要、epoch、revision 和 fence。
  接收方知道准确动作及有效期；审批凭据仍不交给 Agent。
- 过期/撤权/任一会话终止：拒绝新领取，运行中发出原取消信号；实际退出前保留互斥。
- 重启：恢复原授权消费记录与原 operation；未领取动作不自动开始，旧执行若未知则先对账。
- 响应丢失：通过相同意图/原 key 查原 operation，禁止重复领取或更换 idempotency key。
- 副作用未知：保持 needs_reconciliation 和工作区/备份互斥；授权过期不证明副作用不存在。
- epoch 变化：所有旧接棒授权失效，不能从备份恢复重新激活；历史审计记录保留。

## 维护者需决定的范围

1. 是否只允许准确 job 的脱敏状态读取；哪些字段必须移除、谁能提出/撤销。
2. 是否允许开始/续传/取消中的某一项接棒；每日计划变更是否仍永远只限本人。
3. 是否接受受领者必须已有相应普通 scope/角色的双重约束，以及单次 TTL 的具体上限。
4. 设备是否继续完全 HumanOnly；若放开一个准确 job，谁核对本机工作区及完整预检摘要。
5. 生产审计保留、告警和异常副作用的负责人员及人工处置入口。

在这些选择完成前，开发只补本人 CLI/普通业务工具；不实现接棒令牌或授权迁移。
后续实现需单独确认 T01/T06/T08 接口和安全范围，不能由本设计的评审自动授权。

## 后续实现与测试拆分

先由 T01 定最终契约及领域校验，T08/T06 接原接受端，T07 适配准确入口，再做
独立安全测试。必须覆盖错人/错 session/错项目/错摘要/旧 revision、角色/scope
收紧、grant 过期、双会话撤销、同时领取、响应丢失、重启、旧 fence、epoch 变化、
正在取消但未退出、未知外部副作用和跨 origin 重放。现有 HumanOnly 与 native
见证负例必须继续通过。设计评审通过不表示这些测试已经运行或权限已经改变。
